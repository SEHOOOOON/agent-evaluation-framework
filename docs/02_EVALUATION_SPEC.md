# 평가 명세서

문서 ID: `EVAL-SPEC-001` · 문서 버전: `v0.4`

[전체 흐름 실행 계획 FLOW-v1.0](11_RELIABILITY_EVALUATION_PLAN.md)의 판정·집계 설명입니다. **목표 전체 평가와 현재 코드의 개별 검사 경로를 구분**합니다. 과거 V1 합성 집계식·상태를 새 전체 평가의 구현 완료 계약으로 사용하지 않습니다.

## 1. 평가 단위

| 단위 | 의미 |
|---|---|
| 시나리오 | 고정 요청·SRS·공식 TC·시작 상태·독립 기대 조건 |
| 전체 회차 | Agent 1부터 전체 흐름을 한 번 시도. 정상 종료·차단·오류 포함 |
| 단계 시도 | 해당 회차 A1/A2/A3/A4 실행. 최초 생성과 제한 재작성은 같은 회차 안에서 구분 |
| 후보 | A3 계획·코드·시험의 대상 TC. 여러 후보를 모두 기록 |
| 항목 검사 | 특정 역할/연결 기준을 근거와 대조한 판정 |
| 반복 묶음 | 동일 조건의 예정 전체 회차 5개와 비교 결과 |

매 회차 A1~4의 결과 영역과 CP1~4·연결 평가를 남깁니다. 해당 없음·미실행·미평가도 기록 대상이며 성공 산출물을 만들어 채우지 않습니다. 단독 Agent 시험과 저장 기록 재조회는 전체 회차 집계에 합산하지 않습니다.

## 2. 평가 수단

| 수단 | 확인 가능한 범위 | 제한 |
|---|---|---|
| 구조·해시·값 코드 검사 | 필드·연결·원본 보존·명시 값·집계 등 구현된 검사 | 자연어 의미·제품 동작 전체를 보장하지 않음 |
| 실제 제품 시험 증거 | TC가 지정한 조작·관찰·복원 | TC에 빠진 요구사항까지 검증한 것은 아님 |
| 역할별 평가 AI | 요청/TC/계획/보고의 의미·상세도·근거 대조 | 사람 정답과의 교정 필요, 허위 판정 가능 |
| 사람 검토 | 독립 정답, 애매한 분류, Judge 충돌·미평가 확인 | 검토 범위·근거를 기록해야 함 |

제품 시험은 프로젝트 1에서 수행하며 프로젝트 2는 그 결과를 평가합니다. P2가 재시험하면 별도 검증 실행으로 기록하고 원래 Trial에 덧씌우지 않습니다.

## 3. 세 가지 결과를 분리

1. **제품 시험 결과:** 실제 조작 후 기대값과 관찰이 일치했는가?
2. **Agent 업무 평가:** 정해진 역할과 기준에 맞게 생성·시험·분류·보고했는가?
3. **평가 완결성:** 필요한 자료·검사·독립 판단이 충분한가?

예: 제품이 잘못된 온도를 허용해 시험은 FAIL이어도, A3이 정확히 검출하고 A4가 불일치 후보로 보고하면 해당 업무 기준은 충족할 수 있습니다. 반대로 실제 시험 PASS라도 필요한 경계 검사가 TC에 없다면 설계 품질은 별도 위반입니다.

평가용 사람 검토와 공식 SRS/TC 승인도 구분합니다. 평가 통과를 자동 공식 등록으로 연결하지 않습니다.

## 4. 목표 상태 해석

아래는 전체 연결기에 적용할 의미 설계입니다. 현재 모든 출력 스키마에 동일 Enum을 추가한 것은 아닙니다.

- 충족: 적용 기준을 충분한 증거로 만족.
- 위반: 실제 자료에서 기준 위반을 확인. 발생 원인/책임은 별도 기록.
- 검토 필요/미평가: 증거·의미 판단·검사 구현 부족.
- 해당 없음: 요청과 실행 경로상 그 하위 작업이 불필요하다는 근거가 있음.
- 미실행: 계획되거나 도달할 수 있었던 단계가 상위 차단·오류·예산 등으로 실행되지 않음.
- 오류: 입력·수집·환경·평가기 등 처리 실패. Agent 오답으로 자동 전환하지 않음.

정상 재사용 전용 경로에서 신규 코드 생성은 해당 없음이 가능하지만, CP2 차단으로 후보 시험을 못 한 것은 미실행입니다. 두 경우 모두 실제 하지 않은 일을 PASS로 표시하지 않습니다. 기대되는 차단이면 해당 차단 기준의 충족 여부와 후속 미실행을 함께 기록합니다.

## 5. 역할별 일관성 관점

| 대상 | 비교할 핵심 | 주의점 |
|---|---|---|
| A1 | 변경/유지 값·범위·미정 조건·질문·진행 판단 | 같은 오답 반복을 정답으로 취급하지 않음 |
| A2 | 재사용 범위·필수 조작/기대결과·상세도·복원 | TC ID·문장 수가 같아야 하는 것은 아님 |
| A3 | TC→실행 연결→코드의 대상/값/시점·시험 결과·복원/증거 | 현재 화면 연결, 과거 모델 계획, 컴파일, 환경 변동을 구분 |
| A4 | 원본 행 대비 집계·분류·미정/미실행/질문 전달 | 입력 증거가 다르면 분류도 달라질 수 있음 |
| 전체 | 요청→시험 Coverage, 오류 전파·CP 차단·완료 범위 | 최종 보고서만 대조하지 않음 |

전체 흐름에서는 A2 이후 입력도 달라질 수 있으므로 이를 단독 Agent의 확률적 변동으로 단정하지 않습니다. 원인 분리가 필요하면 동일 입력의 보조 시험을 사용합니다.

## 6. 전체 반복 집계 · 구현 목표

- **기준 충족 회차 비율:** 사전 기대 조건을 충족하고 필요한 평가를 마친 회차 / 예정 5회. 오류·미실행·미평가는 분자에 넣지 않고 각각 건수·이유 표시.
- **단계별 도달/평가 가능 수:** 네 역할마다 전체 예정 수·실행 수·부분 자료 수·미실행 수·평가 완료 수를 제시.
- **핵심 일관성:** 비교 가능한 회차 사이의 핵심 계약 값 일치와 비교 가능 수를 함께 표시. 표현 차이와 의미 차이를 구분.
- **최초/수정 후:** 최초 초안 위반과 제한 수정 후 해소 여부를 각각 표시. 재작성 횟수를 새 Trial로 계산하지 않음.
- **차단 정확성:** 독립 정답상 잘못된 산출물의 차단과 정상 산출물의 과잉 차단을 별도로 집계.

예정 5회 중 A3가 3회만 실행됐으면 ‘3회 평가 + 2회 미실행’입니다. 3회 결과를 5회 성공으로 확대하지 않습니다. 미실행 2회가 모두 A3 오류라는 뜻도 아닙니다. 근거 부족·중대한 위반을 평균 점수로 숨기지 않습니다.

## 7. 현재 코드별 출력과 한계

| 경로 | 실제 구현된 판정 | 전체 평가와의 차이 |
|---|---|---|
| `v2_recorded.py` / `run-v2` | FAIL·ERROR·REVIEW, 역할별 CHECKED/PARTIAL/NOT_EVALUATED 등 | 과거 기록의 제한 검사. 품질 점수 null, 최종 품질 PASS 미발급 |
| `openai_judge.py` | 항목 PASS/FAIL/REVIEW/NOT_APPLICABLE, 최종 REVIEW/ISSUES_FOUND/INCOMPLETE | 단일 역할. 근거 없는 PASS 차단은 출력 계약 검사이며 의미 정확도 미교정 |
| `repeatability.py` | 모의 회차별 상태, 충족 회차/예정 수, 비교 가능한 계약 값 일관성 | 실제 생성·제품 실행·네 역할 통합이 아님 |
| `behavior.py` | 저장된 합성 Rule Result 집계, PASS/HOLD/HUMAN_REVIEW | V1 개발·Self-test 경로. 새 전체 흐름 최종 Gate가 아님 |

`behavior.py`의 현재 준수율 분모는 기록된 각 Trial의 **필수 Rule 집합과 N/A가 아닌 반환 Rule 집합의 합집합**입니다. 필수 검사 누락·ERROR·ABSTAIN·필수 Rule의 N/A는 PASS가 아니며 분모에서 빠지지 않습니다. 전체 Trial 누락은 별도 완결성 경고이고, 이 합성 집계식이 전체 예정 회차 분모를 모두 구현했다는 뜻은 아닙니다.

기존 합성 95%·90% Gate와 canonical JSON signature는 보존합니다. 필수 조건 미확인·오류·예정 횟수 불일치는 완결성 문제로 표시하며 실제 Agent 성능 자격을 부여하지 않습니다. 새 평가에서 평균 4점 같은 미교정 임계치를 도입하지 않습니다.

## 8. 반복·예산·데이터 분리

현재 주 시험은 시나리오별 전체 흐름 5회입니다. Development YAML의 3회/5회는 보존한 개발 Case 설정이며 전체 흐름 목표를 대체하지 않습니다. 초기 리허설, Agent 단독 시험, 저장 Run 재조회, 평가기 모의 시험을 별도 표시합니다.

프로젝트 1의 제한 재작성 정책을 고정하고 생성·후보별 계획·평가 호출·오류 시도를 각각 계측합니다. 이전 회차 평가 의견을 다음 생성에 전달하거나 성공 5개까지 추가 실행하지 않습니다. 상세 예산·시작 상태·중단 정책은 [실행 계약](11_RELIABILITY_EVALUATION_PLAN.md#5-전체-흐름-5회-실행-계약)을 따릅니다.

개발·사람 교정·보류용 독립 평가·재발 방지 자료를 구분합니다. 현재 Development 9개 설계, 저장 seed 3개, 합성 예시는 별도 자산이며 실행 완료 횟수로 합산하지 않습니다. 모델 결과를 본 뒤 정답을 맞춰 바꾸지 않습니다.

## 9. 평가기 검증과 남은 구현

기존 자동 테스트는 구조·값·해시·오류 주입·모의 호출·판정 누락·거짓 인용·원본 보호 등을 확인합니다. 실제 역할 의미 판정은 독립 정답과 사람 대조가 필요합니다.

전체 A1~4 호출·자료 수집·각 역할 평가·일부 E2E 코드 검사·회차별 기록 연결기는 무과금 검증했습니다. E2E 의미 충분성·Checkpoint 정확성 교정 및 실제 Live 반복은 남아 있습니다. CLI 종료 0, Judge 항목 PASS, 저장 기록 무위반을 전체 흐름 성능 검증 완료로 설명하지 않습니다. 최신 검증 근거는 [인계 문서](../PROJECT_HANDOFF.md)에 둡니다.
