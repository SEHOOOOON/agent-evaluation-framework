# Agent별 평가 명세 · v2.0

현재 26항목 채점은 `docs/12_DETAILED_RUBRIC.md`의 2.5 기준을 따릅니다. 아래 23개 상위 항목은 저장 Run의 로컬 검사 매핑이며 AI에 코드 본문을 보내라는 뜻이 아닙니다. A3-03의 새 점수는 계획과 구조화 실행 기록을 프로그램으로 대조하며, 코드 생성기 구현은 P1 로컬 회귀검사로 별도 확인합니다.

기존 23개 상위 역할 분류를 유지하고 [세부 판정 기준 26개](12_DETAILED_RUBRIC.md)를 연결했습니다. 사용자 TC 7개 기준은 각각 판정합니다. `judge-openai --role-rubric`으로 담당 Agent의 공통·역할 기준을 적용할 수 있습니다. 정의·Preview·출력 계약 검사와 실제 의미 평가 완료는 구분합니다.

현재 실행 계획은 [프로젝트 1 신뢰성 검증 계획 FLOW-v1.0](11_RELIABILITY_EVALUATION_PLAN.md)을 따릅니다. **주 시험은 전체 흐름 5회이며 매 회차 A1~4 결과와 CP1~4·단계 연결을 각각 평가합니다.** 역할별 기준은 유지하며 실제 자동 수집·반복 호출·의미 평가 연결 여부와 구분합니다. 단독 Agent 시험은 원인 분석용입니다.

## 목적과 현재 구현

공통 무결성 검사와 역할별 업무 품질을 구분합니다. 실행 가능한 항목 목록·검사 매핑은 `src/eval_harness/agent_rubric.py`에서 관리합니다. `run-v2`가 사례마다 공통·Agent 1~4·E2E 결과를 JSON과 HTML에 생성합니다. 기존 자동 검사를 역할별 목표에 연결한 것이며 아직 없는 의미 평가기를 구현했다고 표시하지 않습니다.

`run-v2`의 23개 상위 역할 표시는 코드 검사 결과가 모두 있어도 의미 검토가 필요하면 PARTIAL입니다. 자료나 구현이 없으면 NOT_EVALUATED입니다. CHECKED는 명시된 자동 검사 범위이며 Agent 전체 PASS가 아닙니다. 이 경로의 quality_score는 null입니다. 별도 26항목 `full-flow`/`judge-openai`는 score-0-5-v2로 0~5점을 기록하고 미평가·위반을 함께 표시합니다. 점수는 사람 교정 전 잠정 평가이며 정확도나 완성도가 아닙니다.

위 표의 구현 설명은 `run-v2` 저장 검사 범위입니다. 추가한 `full-flow`는 역할별 Judge 자료와 일부 E2E 대조를 연결했고, E04에는 원본/사본 자산 목록·해시 전후 검사를 구현했습니다. 실제 승인 동작 시험이나 전체 의미 판정의 검증 완료를 뜻하지 않습니다.

현재 Agent 3의 화면 연결, 과거 모델 계획, 결정론적 컴파일러, 실행 환경을 원인 분석에서 구분합니다. 현재 연결표 TC는 위치 생성용 AI를 호출하지 않으며 의미 검토는 유지합니다. Agent 4는 규칙 기반 분석기이며 제품 시험 실패를 Agent 실패로 자동 치환하지 않습니다.

### 전체 회차에서의 평가 범위

- A1·A2의 초안과 CP 검사·제한 수정 후 결과를 구분하고, 후속 역할에는 그 회차의 실제 산출물을 전달합니다.
- A3는 후보별 계획·CP3·실제 관찰·복원·증거와 관련 기존 TC 실행을 함께 봅니다. 컴파일 코드 구현은 로컬 회귀검사, 기록된 값의 일치는 프로그램, 의미와 주장 범위는 AI가 담당합니다. 다중 후보를 한 성공 후보로 대표하지 않습니다.
- A4는 매 회차의 중립 실행 입력과 분석·보고·CP4를 대조합니다. 최종 보고서만 읽고 A1~3도 통과했다고 판단하지 않습니다.
- CP 차단으로 후속 역할이 실행되지 않았다면 미실행입니다. 재사용 전용 경로에서 신규 생성이 불필요한 경우와 구분합니다.
- 독립 기준과 실제 인계를 대조해 오류 차단·과잉 차단을 확인하고, E01~E04로 전체 완료 범위·질문/실패 전달·자산 보호를 따로 평가합니다.

`full-flow`가 전 단계 실행·자료 수집·역할별 평가와 일부 E2E 코드 검사를 연결합니다. 단일 역할 프로필 네 개를 호출했다고 E2E 의미 충분성까지 평가된 것은 아니며, 실제 Live 리허설·사람 교정은 남아 있습니다.

### 판정 기준

- 코드 검사: 정의된 검사 조건을 만족/위반하는 이진 판정. 같은 조건에 의도적 오류와 정상 대조군을 넣어 평가기 자체를 시험합니다.
- 의미 검토: 충족/보완 필요/근거 확인 필요/해당 없음 + 실제 인용·이유. 사용자 TC 정답지는 A2의 상세도 기준이며 다른 항목의 정답을 대체하지 않습니다.
- Critical 위험 표시는 해당 항목에서 발생할 수 있는 위험의 중요도입니다. PARTIAL인 Critical 항목을 통과로 취급하지 않습니다. 기존 검사 FAIL은 전체 FAIL을 유지하며 평균으로 상쇄하지 않습니다.
- 26항목의 0~5점 기준은 [세부 기준](12_DETAILED_RUBRIC.md)을 사용합니다. 사람 교정 전 점수는 잠정값이며 임의 평균 합격점이나 최종 승인 기준으로 사용하지 않습니다.

## 현재 데이터와 다음 실행

`recorded_v1.jsonl`의 3개 저장 사례에 23개 상위 항목을 각각 표시합니다. 이는 69개 전문 평가가 완료됐다는 뜻이 아닙니다. 저장 기록 자동 검사 수와 역할 항목 수를 더해 통과율로 사용하지 않습니다. 새 세부 프로필은 별도 Judge 패킷에 적용하며 과거 보고서를 소급 갱신하지 않습니다.

1. 기존 기록은 자동 근거와 미평가 항목을 표시하고 TC 직접 검토는 별도 문서로 연결합니다.
2. 요청별 필수 조건·금지 조건·영향 범위와 A4 중립 신호 정답을 작성해 사람 검토를 받습니다. 이미 받은 TC 상세도 기준을 다시 요청하지 않습니다.
3. 전체 A1~4 수집·평가 연결의 무과금 검증 후 전송 Preview·예산 승인 범위에서 전체 리허설과 5회 시험을 수행합니다. 전 단계 오류가 후속 Agent에 전파된 경우 후속 Agent만 탓하지 않도록 단계별 실제 입력을 보존합니다.
4. 교정된 기준으로 같은 사례의 수정 전후를 비교합니다. 해결 사례는 원본·판정·수정 버전 근거를 보존해 Agent 회귀 집합으로 추가합니다.
