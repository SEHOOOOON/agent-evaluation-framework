# 비용 자동 계산 설계안 (결정 필요 · 구현 안 함)

작성: 2026-10-16 KST · 상태: **사용자 결정 대기**. 단가를 사용자가 확인하기 전이라 코드·설정 파일을 만들지 않았다.

2026-10-17 확인: 사용자가 OpenAI Usage 화면으로 2026-10-15 하루 청구 **$2.00 / 요청 16건 / 토큰 618,724**를 확인했다. 같은 날 기록 합산(가정 단가 입력 $2.5/M·출력 $10/M)으로 낸 추정 약 $1.9와 일치해, 가정 단가가 실제와 크게 다르지 않고 기록되지 않은 과금도 보이지 않는다. 단가표 파일 작성(①-가)은 공식 가격 페이지 확인 후 진행한다. 같은 날 지출 항목(사용자 화면): gpt-6.1-sol 캐시 쓰기 $1.448(72%), 캐시된 입력 $0.004, 일반 입력 $0, 출력 $0.546, 캐시 쓰기-12시간 $0. 입력 전부가 캐시 쓰기로 청구되고 할인 입력은 거의 없었다(IMP-012에서 찾은 앞부분 불일치와 일치). 캐시된 입력 단가는 캐시 쓰기의 약 1/10로 추정되며, 12시간 보존 옵션 단가는 미확인.

## 1. 지금 무엇이 불편한가

실행할 때마다 사람이 토큰 수를 옮겨 적고 단가를 곱해 인계 문서에 적는다(예: 2026-10-15 "사용량 기반 추정 약 $1.9, 실제 청구액 미확인"). 같은 계산을 매번 손으로 하다 보니

- 단가 출처·적용일이 기록마다 다르게 적히고,
- 캐시 쓰기/읽기를 어떻게 가정했는지가 문장에 섞여 있으며,
- 오류 난 시도의 사용량은 기록이 없어 합계에서 빠진다.

## 2. 지금 저장되는 사용량 (코드 확인 결과)

| 위치 | 저장 내용 | 빠진 것 |
|---|---|---|
| 생성 호출 `call_ledger.json` (`flow_worker.py`) | 응답의 `usage` 전체(`model_dump`) — 캐시 상세가 있으면 함께 저장됨 | 오류 시도(응답 없음)의 사용량 |
| 채점 호출 `result.json` (`openai_judge.py`) | `input_tokens`, `output_tokens`, `total_tokens` 세 값만 | 캐시 읽기·쓰기 상세, 오류 시도 |

즉 채점 쪽은 캐시 상세를 버리고 있어서, 단가표를 넣어도 "전부 일반 입력" 또는 "전부 캐시 쓰기"의 범위로만 계산할 수 있다.

## 3. 제안 구조

1. **단가표 파일** `config/pricing.json`(사람이 확인 후 작성, Git 추적)

   ```json
   {"version": "pricing-2026-10-XX", "checked_by": "사람 이름", "checked_at": "2026-10-XX",
    "source_url": "https://developers.openai.com/api/docs/models/<모델>",
    "models": {"gpt-6.1-sol": {"input": 2.00, "cached_input_read": null, "cache_write": 2.50, "output": 10.00,
                               "unit": "USD per 1M tokens", "tier": "Standard"}}}
   ```

   위 숫자는 인계 문서 2026-10-11 기록에 적힌 값을 **예시로만** 옮긴 것이다. 실제 값은 사용자 확인 후 채운다.

2. **실행 후 표시**: `result.json`과 `summary.json`(재채점)에 `cost_estimate` 칸 추가

   ```json
   "cost_estimate": {"pricing_version": "pricing-2026-10-XX",
     "generation": {"calls_with_usage": 9, "calls_without_usage": 1, "usd_low": 1.21, "usd_high": 1.48},
     "judge": {"calls_with_usage": 4, "calls_without_usage": 0, "usd_low": 0.42, "usd_high": 0.51},
     "note": "사용량 기반 추정. 실제 청구액 아님. 사용량 없는 시도는 합계에 포함하지 않음"}
   ```

   - `usd_low`/`usd_high`: 캐시 상세가 없으면 "전부 일반 입력"과 "전부 캐시 쓰기"로 범위를 낸다(지금 손으로 하는 방식과 같음). 캐시 상세가 있으면 두 값이 같아진다.
   - 사용량이 없는 시도는 개수로만 표시하고 금액을 추정하지 않는다(예: "오류 1회는 금액 미상").
   - 단가표가 없거나 모델이 표에 없으면 `"status": "PRICING_NOT_CONFIGURED"`만 남기고 계산하지 않는다.

3. **실행 전 미리보기**는 바꾸지 않는다. 입력 크기로 토큰을 짐작하는 방식은 오차가 커서(2026-10-11 예상 $0.70~$1.50 vs 실제 사용량 기준 $0.50~$0.61) 자동화해도 신뢰도가 낮다.

## 4. 결정이 필요한 것

| 질문 | 선택지 | 권장 |
|---|---|---|
| ① 단가 확인 | (가) 사용자가 공식 페이지에서 확인해 단가표 작성 / (나) 단가표 없이 토큰 합계만 자동 표시 | (가). 확인 전까지는 (나)만 먼저 구현 가능 |
| ② 채점 캐시 상세 저장 | (가) `usage` 전체를 저장하도록 변경(승인 해시와 무관한 결과 기록 변경) / (나) 현행 유지(범위로만 계산) | (가). 과거 결과는 바꾸지 않음 |
| ③ 표시 위치 | (가) `result.json`·재채점 `summary.json`만 / (나) 대시보드에도 표시 | (가) 먼저 |

예: ①(나)만 선택하면 다음 실행부터 "생성 9회 입력 210,000 / 출력 12,000 토큰, 사용량 없는 시도 1회"가 자동으로 남고 금액은 사람이 계산한다.

## 5. 부작용·한계

- 단가가 바뀌어도 과거 결과의 금액은 다시 계산하지 않는다(당시 `pricing_version`을 함께 남겨 구분).
- 자동 금액은 여전히 추정이며 실제 청구액 확인을 대신하지 않는다.
- 단가표 파일이 평가 코드 해시(`p2_pin`)에 들어가면 단가만 바꿔도 이전 미리보기 승인값을 못 쓰게 된다. 비용 표시는 점수와 무관하므로 해시에서 제외하는 쪽을 권장한다.
