# 역할별 시나리오 조건 검사

## 무엇을 추가했나

기존 파일 해시·집계 검사에 더해, 데이터셋에 명시한 예상 조건과 저장된 Agent 출력을 직접 대조합니다. 평가 대상 프로그램을 실행하거나 모델을 호출하지 않습니다. 기존 `recorded_v1.jsonl` 경로도 유지합니다.

| 역할 | 이번 데이터셋의 검사 |
|---|---|
| Agent 1 | 확정 요청은 진행, 색상 미정은 부분 진행, 사용자 확인 질문 보존 |
| Agent 2 | MED 신규 후보와 기존 HIGH TC 재사용 구분, 기대결과 수, 독립 실행·복원 선언 |
| Agent 3 | 동일 Assertion의 기대값과 적용 후 시점, 기준 동작이 적용인지, 복원 확인 존재 |
| Agent 4 | 시험 통과 권고, 실패의 불일치 후보 보고, 미정 조건의 사람 검토 권고 |
| 전체 연결 | 사용자 확인 질문의 최종 보고 전달 |

Agent 2의 선언과 기대결과 개수를 확인했다고 TC의 문장 상세도·전체 Coverage가 입증되는 것은 아닙니다. Agent 3의 복원 확인 개수를 확인했다고 복원 의미·코드·실행이 모두 검증되는 것도 아닙니다. 사용자 TC 정답지는 계속 별도 상세도 기준으로 사용합니다.

## 정답의 출처와 한계

`benchmarks/v2/scenario_v1.jsonl`은 3개 기존 기록의 개발용 계약 회귀 초안입니다. 각 조건에 검사 이유와 근거를 둡니다. 사용자 예시의 상세도 기준 지정과, 이번 시나리오 정답 초안의 사람 승인은 다릅니다. 후자는 아직 DRAFT입니다.

일부 조건은 해당 저장 계획의 ID·문장·개수에 맞춘 고정 비교입니다. 예를 들어 ACT-003은 이 계획에서만 적용 동작입니다. 다른 정상 표현·다른 계획 ID를 자유롭게 생성하는 Live 평가에 그대로 적용하면 오탐할 수 있습니다. 따라서 독립 Holdout·새 Agent 성능·분류 정확도로 사용하지 않습니다. 자연어 의미 동등성도 판단하지 않습니다.

## 검사와 판정

- `equals`: JSON 값과 타입을 정확히 대조합니다.
- `contains`: 선택된 행 중 한 행이 지정 필드를 함께 만족하는지 확인합니다. 서로 다른 행의 값·시점을 합쳐 통과시키지 않습니다.
- `count`: 명시된 경로로 선택된 항목 수를 대조합니다. 기존 TC만 재사용해 신규 후보가 0개인 정상 계약도 표현할 수 있습니다.
- 자료 누락·잘못된 JSON·경로 타입 오류는 ERROR입니다. 읽을 수 있는 값의 불일치는 FAIL입니다. 원인 책임은 자동으로 Agent에 돌리지 않습니다.
- 전체 자동 검사 무위반은 REVIEW입니다. 사람 정답 확정·의미 검토가 남으므로 PASS나 품질 점수를 발급하지 않습니다.

원본 저장소와 Run의 전후 해시를 확인하고, 데이터셋·평가기·역할 기준·시나리오 검사 모듈의 해시를 baseline에 기록합니다. 과거 실행 시점 commit은 미기록이면 unknown이며, 평가 시점 commit과 구분합니다.

## 과거 질문 누락을 보는 방법

색상 미정 Run은 당시 Agent 1 질문을 최종 보고에 전달하지 않았습니다. 현재 전달 계약을 대조하면 FAIL이 맞습니다. 이것은 과거 기록의 공백이며, 최신 프로젝트 1 코드가 같은 오류를 다시 냈다는 뜻은 아닙니다. 최신 코드는 `734aace`에서 보완돼 있지만 이번 작업에서는 새 통합 모델 실행을 하지 않았습니다. 과거 기록을 고쳐 PASS로 만들지 않습니다.
