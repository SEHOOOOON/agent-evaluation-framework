# 세부 평가 기준과 역할별 평가자 입력

기준 버전: `role-rubric-2.0`. 기존 23개 상위 역할 분류는 유지하고 26개 세부 판정 항목으로 연결합니다. Agent 2의 상세도는 사용자 TC의 7개 항목으로 나눕니다. 정의 파일은 [detailed_rubric.py](../src/eval_harness/detailed_rubric.py)이며 각 항목에 적용 조건, 필요한 증거, 통과 조건, 실패 조건, 정상/실패 예시가 있습니다.

**항목을 정의하고 평가자 입력에 연결한 것과 실제 모델 평가가 정확하다는 것은 다릅니다.** 현재 자동 검사는 프로필 무결성·필수 자료 키 존재·출력 계약 검사입니다. 실제 의미 평가, 사람 정답과의 교정, 전체 프로젝트 1 반복 실행은 별도 검증이 필요합니다.

현재 주 시험은 [FLOW-v1.0](11_RELIABILITY_EVALUATION_PLAN.md)의 **전체 흐름 5회·매 회차 A1~4 및 Checkpoint·연결 평가**입니다. 단독 역할 패킷은 그 평가의 구성요소이지 전체 시험의 대체물이 아닙니다. 아래 Agent 2 예시를 ‘Agent 2만 먼저 실행하는 계획’으로 해석하지 않습니다.

## 1. 교육자료에서 가져온 내용

사용자 제공 `세션5.mp4` 29분 32초의 전체 음성을 로컬로 자동 전사해 읽고, 전사가 불완전한 10개 구간을 재전사했습니다. 전 시간대의 30초 간격 발표 화면 59장 및 발표 PDF와 대조했습니다. 자동 전사에는 기술 용어·고유명사 오류가 있으므로 공식 자막으로 보지 않습니다.

- 10:20 전후: 읽을 자료, 사용할 도구, 막혔을 때 재시도, 결과 검증을 각각 실행 규칙으로 설명합니다.
- 18~19분대: 정상뿐 아니라 경계·정보 부족·정책 우회·지침 공격·권한 밖 요청을 평가 입력으로 구성합니다.
- 24~27분대: 허위 완료, 올바른 거절의 오판, 구체적인 다음 행동, 업무별 판정 기준을 구분합니다.
- [강연자의 실습 지침](https://github.com/devkimchi/foundry-evaluation-engineering-demo/blob/main/data/agent-v2-instruction.txt)과 [사례별 기대 행동](https://github.com/devkimchi/foundry-evaluation-engineering-demo/blob/main/data/evaluation-dataset.jsonl)을 대조했습니다. 강연 실습은 지침 효과 비교를 위해 실제 업무 도구를 연결하지 않았습니다.
- [공식 OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 작업별 구체적 기준, 정상·예외 사례, 사람 판정과의 교정 원칙도 참고했습니다.

아래 QA 판정은 교육의 공식 지표 목록을 복사한 것이 아니라 우리 계약에 맞춘 적용입니다. 교육의 HR 예시 가중치 40/30/20/10과 임의 평균 합격 점수는 사용하지 않습니다.

TC-R01~06은 이미 받은 사용자 TC를 기준으로 합니다. TC-R07은 기존 프로젝트 복원 계약입니다. 예시의 온도·색상·버튼 클릭 횟수를 모든 요구사항에 강요하지 않습니다. 읽기 전용 TC는 근거를 들어 복원 해당 없음이 될 수 있습니다. 준비 동작마다 제품 기대결과를 억지로 추가하지 않습니다.

예를 들어 온도 표시만 요청했다면 알림 색상 미정 때문에 실패시키지 않습니다. 반대로 알림 색상 변경을 요청했는데 목표 색상이 없다면 그 값만 질문합니다. 대상이 안전하게 분리 가능할 때만 확정된 부분을 진행합니다.

## 3. 역할별 전체 기준으로 Preview 만들기

```bash
python -m eval_harness judge-openai --packet benchmarks/v2/role_packet.example.json --model MODEL_ID --role-rubric
```

- API 키나 외부 호출 없이 Preview를 생성합니다. 모델 ID는 사용자가 선택하며 이번 변경으로 모델을 바꾸지 않습니다.
- 기존 패킷의 `rubric`을 해당 Agent의 공통+역할 기준으로 교체합니다. A1 6개, A2 10개, A3 6개, A4 6개입니다. Agent 4는 규칙 기반 분석기 산출물을 평가하는 것이며 생성 Agent로 바꾸지 않습니다.
- E01~E04는 정의와 정상/실패 예시는 있지만 이 단일 Agent 호출에 넣지 않습니다. 전체 흐름 증거 평가기는 후속입니다.
- `--role-rubric` 없는 기존 호출은 호환성을 유지하며 `CUSTOM_SUBSET`으로 표시합니다. 일부 항목 평가를 전체 Agent 평가로 표현하지 않습니다.
- 역할 프로필로 선언한 항목의 누락·내용 변경·다른 역할 혼입을 거부합니다. 원본 파일은 바꾸지 않으며 프로필 적용 후 Preview 해시가 달라집니다. 예전 해시로 실행할 수 없습니다.
- 실제 실행은 별도 사용자 승인과 Preview에 맞는 `--execute --approval-sha256 ...`가 필요합니다. 호출·재시도 한도와 비밀정보 검사는 유지합니다.

### 필요한 자료

| sources 키 | 내용 |
|---|---|
| context | 원래 요청·SRS·해당 회차 실제 앞 단계 출력·기존 TC·역할 및 별도로 구분한 독립 판정 기준 |
| artifact | 이번에 평가할 해당 Agent 산출물 |
| trace | 실제 전달·조작·계획/코드·수정 이력 등 해당 기준을 확인할 기록 |
| inventory | 당시 UI 요소·표시·활성 상태·허용 행동 근거 |
| execution | 실제 실행 행·관찰·복원·화면/로그 등 검토에 필요한 증거 내용 |
| approval | 전체 흐름의 유효한 승인·자산 변경 기록; 현재 단일 역할 프로필에서는 사용하지 않음 |

모든 키를 모든 역할에 강요하지 않습니다. 항목별 `evidence_requirements`로 구분합니다. 단독 `judge-openai`는 사람이 자료를 선정합니다. `full-flow`는 실제 회차의 역할별 요청·출력·검사·계획/코드·실행 JSON을 수집하며 로컬 작업 경로 치환을 기록합니다. 전체 HTML·화면·Trace는 전송하지 않고, 남은 민감 패턴이나 크기 초과는 전송 전 차단합니다.

전체 연결기에서는 실제 앞 단계 출력을 보존해야 합니다. 잘못된 분석을 검토된 정답으로 교체하면 실제 오류 전파를 평가할 수 없습니다. 평가자에게 전달한 독립 정답·평가 의견은 프로젝트 1의 생성 입력으로 다시 보내지 않습니다.

예시 패킷에는 실제 전달 이력 `trace`가 없습니다. 따라서 공통 2개는 `MISSING_EVIDENCE`, TC 관련 8개는 `READY_FOR_REVIEW`입니다. 후자는 자료 키가 있다는 뜻이지 의미 평가 합격이 아닙니다. 빈 값·빈 목록·빈 객체도 증거 누락으로 봅니다. 비어 있지 않은 내용의 진실성·충분성은 별도 검토가 필요합니다.

필수 자료가 없을 때 AI가 PASS나 NOT_APPLICABLE을 반환하면 출력 계약 오류로 처리합니다. 이는 Agent의 오답 확정이 아니라 평가자의 잘못된 판정 형식입니다. 근거 부족은 REVIEW, 현재 자료로 명확히 확인되는 위반은 FAIL로 남길 수 있습니다. 인용 존재 검사만으로 판단의 논리적 정확성을 보장하지 않습니다.

## 4. 정상·오류 대조와 평가기 검증

- 26개 항목 각각의 정상/실패 예시를 정의했습니다. 이 52개 짧은 예시는 기준 설명용이며 독립된 Live Benchmark나 사람 정답으로 확정한 결과가 아닙니다.
- development 데이터는 목표 색상이 빠진 요청과 알림 변경을 요청하지 않은 정상 요청을 구분하도록 보완했습니다. 색상·문구·갱신 주기를 모두 무조건 필수 Gap으로 두지 않습니다.
- 자동 테스트는 역할 선택, 기준 변조/누락 차단, 사용자 TC 7개 분리, 근거 누락 시 PASS/해당 없음 차단, 키 없는 Preview, 기존 코드 FAIL 보존을 검증합니다.
- 의미의 잘못된 합격/불합격을 실제로 측정하려면 검토된 입력·산출물·독립 사람 판정으로 평가 모델을 호출하고 비교해야 합니다. 이번에는 유료 호출하지 않았습니다.
- API 오류와 Agent 오류, 제품 시험 실패와 Agent의 정확한 실패 보고를 구분합니다. 오류 수·미평가 범위를 숨기거나 치명적 위반을 평균으로 상쇄하지 않습니다.

최신 테스트와 실행 기록은 [인계 문서](../PROJECT_HANDOFF.md)에만 기록합니다. 다음 연결 작업은 **프로젝트 1 전체 A1~4 실행·단계별 자료 수집·역할/연결 평가·Preview**입니다. 무과금 검증과 독립 정답 준비 후, 승인된 전체 경로 리허설 및 고정 조건 5회 시험을 진행합니다. 문제 역할 단독 실행은 원인 분석에 사용합니다.
