# 구현 매핑

문서 ID: `MAP-001` · 문서 버전: `v0.4`

[FLOW-v1.0 실행 계획](11_RELIABILITY_EVALUATION_PLAN.md)을 코드와 대조한 표입니다. 전체 흐름 반복이 목표이고 단독 시험·저장 감사·모의 호출은 보조입니다. 아래 ‘미구현’을 새 기능으로 간주하지 않습니다.

## 1. 프로젝트 1과 프로젝트 2 경계

프로젝트 1 V2는 이미 `pipeline`(A1~3·후보 시험), `execute`(후보 확인·관련 기존 TC 실행), `agent4`(규칙 분석·보고) 진입점이 있습니다. `full_flow.py`와 `flow_worker.py`가 이들을 독립 사본에서 순서대로 호출하고 역할별 자료·평가를 연결합니다. 무과금 모의 분기와 현재 P1 코드의 차단 경로를 확인했으며 실제 모델 성공 경로는 승인 후 리허설 대상입니다.

초기 V1 Prompt·3-Tier·Review 문서에 기반한 `rules/project1_agent_rules.yaml`과 Fixture는 보존합니다. V2 생성 계약을 V1 샘플 필드와 혼동하지 않습니다. 새 평가 입력은 대상 버전의 실제 구조화 계약을 사용해야 합니다.

## 2. 현재 구현 모듈

| 모듈 | 실제 역할 | 미구현/해석 제한 |
|---|---|---|
| `v2_recorded.py` | 과거 V2 Run 읽기·Run ID·인계 해시·TC/실행/보고 계약 검사 | 새 프로젝트 1 실행 안 함. ID 미기록은 미평가, 명시된 다른 ID는 무결성 위반 |
| `scenario_oracle.py` | 개발용 고정 조건과 저장 JSON 비교 | 자유로운 신규 TC 의미 비교 아님 |
| `agent_rubric.py` | 23개 상위 역할 항목과 자동 검사 매핑 | 미평가만 있으면 미평가, PASS와 미평가가 섞이면 부분 확인. 26개 세부 기준/AI 점수를 대신하지 않음 |
| `detailed_rubric.py` | 26개 세부 기준, 역할별 프로필·필수 자료 키 검사 | 의미 충분성·E2E 통합 미완료 |
| `openai_judge.py` | 단일 역할 패킷 Preview·승인 해시·평가 호출·출력/인용 검사 | 전체 회차 조정은 full_flow가 담당. 사람 교정 미완료 |
| `repeatability.py` | 모의 반복·호출 한도·오류·중복·계약 값 비교 | 실제 SDK 생성 Adapter나 전체 반복기가 아님 |
| `behavior.py` | 기존 합성 Recorded Trial 검증·지표·Gate 집계 | V1 개발 정책. 실제 Live 전체 성능 판정 아님 |
| `fixtures.py`·`runner.py` | V1 저장 산출물 감사·정상/오류 대조 | 신규 Agent 실행 안 함 |
| `full_flow.py`·`flow_worker.py` | 해시 승인·독립 사본·A1~4 실행·생성/재작성/근거 검토 합산 한도·초안 포함 수집·역할 Judge·일부 E2E 검사·ZIP 증거 보존 | 이전 P1의 재사용·실행·A4 완료 사례 있음. 최신 P1 호환성은 로컬 검사이며 전체 의미 일관성·CP 정확성·사람 교정 미검증 |
| `web/` | 저장 V2·전체 FLOW·평가기 자체 검증 분리 조회 | UI 유료 실행·독립 Judge 기록 통합 안 함 |

실제 데이터는 Development YAML 9개 Case, 저장 V2 seed 3개, 별도 합성 Fixture입니다. 같은 이름의 Case가 있다고 실행을 완료한 것은 아닙니다.

## 3. 현재 CLI

| 명령 | 실행하는 것 |
|---|---|
| `run --suite project1-audit --mode fixture` | V1 Snapshot 탐지 검사 |
| `run --suite known-good --mode fixture` | 정상 Fixture 오탐 검사 |
| `behavior-self-test` | 합성 Trial 집계기 |
| `run-v2 --target ../qa-agent-pipeline-v2` | V2 저장 기록 읽기 전용 검사 |
| `repeat-self-test --trials 5` | 모의 응답 반복 |
| `judge-openai --packet ... --model ... --role-rubric` | 기본 전송 Preview. 승인 후 execute 옵션에서 별도 평가 호출 |
| `dashboard` | 저장 V2 평가 조회 + 별도 평가기 자체 검증 |

`full-flow --target ... --spec ...`는 기본 Preview입니다. 1회/5회 명세와 생성·평가 상한을 고정하고 별도 승인 해시가 있어야 실행합니다. `run-v2`나 `repeat-self-test`를 실제 5회 실행으로 설명하지 않습니다.

## 4. 전체 연결기에서 구현할 것

아래는 구현 목표와 점검 목록입니다. 호출·수집·역할 패킷·한도·회차 기록은 연결했고 이전 P1 버전의 재사용 경로에서 A4까지 실행한 사례가 있습니다. 이를 최신 P1의 신규 TC 전체 경로·의미 평가·5회 반복 완료로 확대하지 않습니다. 기준 버전별 최신 상태는 [인계 문서](../PROJECT_HANDOFF.md)를 따릅니다.

1. 프로젝트 1 고정 버전을 독립 작업 위치에서 실행하고 동일 제품 시작 상태를 준비.
2. 전체 회차·각 Agent·후보·CP·실제 Run의 ID와 입력/출력 해시 연결.
3. 각 단계 최초/수정 산출물·CP 판정·후보/기존 TC 실행·A4 최종 보고 수집.
4. A1~4 역할별 패킷과 코드 검사, E01~E04 연결 평가를 조합. 마지막 보고서 하나로 대체하지 않음.
5. 정상·부분 진행·차단·기존 TC만 재사용·다중 후보·환경/평가 오류 분기 보존.
6. 생성/평가/재시도 호출 예산과 응답·오류 기록. 예산·안전 중단을 별도 표시.
7. 회차 종료 자료 중 이번 예산으로 평가할 역할들의 입력을 모두 사전 점검한 후 순차 평가하고 다음 회차를 준비. 준비 실패 시 해당 묶음의 Judge는 호출하지 않음. 평가 의견을 생성에 피드백하지 않음.
8. 예정 5회 및 역할별 도달/평가 가능 수·일관성·최초/수정 후 결과 보고.

A3의 A2 실행 정의·화면 연결·컴파일러·제품 실행 증거와 A4 규칙 분석 결과를 포함합니다. 과거 모델 계획은 별도 계약으로 구분합니다. 실제 리허설·5회 시험과 단독 원인 분석의 증거를 구분합니다.

## 5. 대시보드·결과 경로

- 대시보드 첫 화면은 저장 V2 결과를 읽습니다. A1~4와 전체 연결을 비교하고 기준별 근거를 펼칩니다. 전체 실행 기록은 별도 탭이며 무과금 검증과 실제 모델 시험을 구분합니다. 실제 5회 시험은 아직 미실행입니다.
- 역할 상태는 저장 항목의 표시용 요약입니다. FAIL → ERROR → PARTIAL → CHECKED → NOT_EVALUATED 우선순위이며 확인/미평가가 섞이면 PARTIAL입니다. 사례 판정은 저장 JSON을 그대로 사용하고 새 품질 점수를 만들지 않습니다.
- `run-v2`: `evaluation-runs/V2-EVAL-.../`의 baseline·result·report.
- `repeat-self-test`: `evaluation-runs/REPEAT-SELFTEST-.../`의 모의 계획·이벤트·회차 원본·result·report.
- `judge-openai`: `evaluation-runs/JUDGE-.../`의 패킷·Preview·이벤트·판정.
- `full-flow`: `evaluation-runs/FLOW-.../`의 고정 Preview·회차 기록·원본 증거 ZIP·역할별 패킷/판정·구조/텍스트 비교. 의미 일관성 통과 판정이 아닌 비교 자료입니다.
- 과거 문서의 `behavior-runs/` 트리는 제안이었고 현재 전체 Live Runner 산출물 경로로 구현되지 않았습니다.

JSON이 해당 경로의 결과 원본이며 UI가 새로 판정하지 않습니다. 서로 다른 경로의 수치·상태 Enum을 하나의 완료된 전체 평가 결과처럼 합치지 않습니다.

## 6. 원본 보호와 검증

`full-flow-0.9`는 자동화 코드의 연결 해시를 로컬에서 확인하고 본문은 AI에 보내지 않습니다. `execution_observations.py`는 신규 TC·계획·구조화 시험 관찰값·결과를 대조하여 A3-03을 프로그램으로 확인합니다. 실제 읽기 함수와 코드 생성기는 P1 로컬 회귀검사 대상이고, TC 의미·화면 선택 적절성·실행/복원 주장의 타당성은 AI 평가에 남습니다. 중간/최종 시험 로그의 해시·경로·용량 제한은 유지하며, 기록이 부족하거나 지원하지 않는 과거 비교는 점수를 만들지 않습니다. 과거 점수·원본 실행은 변경하지 않습니다.

저장 검사 경로의 원본/출력 경로 분리·해시 대조·허용 Artifact 조회를 유지합니다. 연결기는 회차별 새 작업 위치·동일 파일 해시·자산 추가/변경 탐지·증거 ZIP 보존을 구현했습니다. 제품 초기 상태/복원과 분류 정확성의 실제 Live 검증은 남아 있습니다. 별도 작업 위치를 OS 보안 격리로 설명하지 않습니다.

프로젝트 1 공식 SRS/TC·포트폴리오·원본 Run을 덮어쓰지 않습니다. 외부 보고·사람 등록 승인은 반복 평가에 포함하지 않습니다. 구현 상태 변경 시 이 표·실행 계획·README·인계 문서를 함께 갱신합니다.
