# 평가 대시보드

문서 ID: `DASH-001` · 문서 버전: `v0.4`

## 실행

```bash
python -m eval_harness dashboard --port 8766
```

기본 포트는 8766입니다(8765는 프로젝트 1 UI 기본값). 서버는 127.0.0.1에만 열리며 공개 배포하지 않습니다.

## 첫 화면: 저장 결과 검토

1. **평가 기록 선택:** 기존 `evaluation-runs/V2-EVAL-.../result.json`을 읽습니다.
2. **사례 요약:** 검토 사례·위반 발견·검토 필요·평가 오류를 확인합니다. 서로 다른 과거 사례 수이지 새 실행 횟수가 아닙니다.
3. **사례별 표:** A1 요구사항, A2 TC, A3 계획·코드·시험, A4 분석·보고, 전체 연결을 비교합니다.
4. **근거 확인:** 상태를 누른 뒤 아래의 기준을 펼치면 검사 ID·저장된 이유·판정을 볼 수 있습니다. 공통 기준은 상세 영역에 있습니다.

실패/오류 사례를 먼저 선택합니다. 기록을 바꾸거나 새로고침해도 Agent를 실행하거나 API를 호출하지 않습니다. 기록이 없으면 안내만 표시하고, 깨진 기록은 오류로 표시하며 이전 정상 기록으로 몰래 대체하지 않습니다.

## 상태를 읽는 법

| 표시 | 의미 |
|---|---|
| 자동 확인 | 연결된 자동 검사 범위 확인. 의미 정확성 전체 통과가 아님 |
| 부분 확인 | 일부 확인됐지만 확인되지 않은 범위가 남음 |
| 미평가 | 해당 항목 평가 근거가 없음 |
| 위반 발견 | 저장 평가에서 기준과 불일치 발견 |
| 검토 필요 | 사례의 의미·정답에 대한 검토가 남음 |
| 평가 오류 | 평가를 완료하지 못함 |

역할 칸은 항목 상태의 표시용 요약입니다. 위반·오류를 먼저 표시하고, 자동 확인과 미평가가 섞이면 부분 확인으로 표시합니다. 사례 판정은 저장 결과를 그대로 사용합니다. UI가 새로운 합격률·품질 점수를 판정하지 않습니다.

**제품 시험 FAIL과 Agent 평가 FAIL은 다릅니다.** 과거 Run을 현재 검사 계약에 대조한 결과도 있으므로, 저장된 위반을 현재 코드의 결함으로 단정하지 않습니다. ‘원본 해시 유지’도 저장 평가 당시의 확인이지 현재 파일 재검사가 아닙니다.

## 별도 탭: 평가기 자체 검증

기존 V1 Snapshot과 정상 Fixture의 규칙 탐지·오탐을 확인합니다. 기존 실행 버튼·단계별 Rule Check·Finding·입출력·Evidence·보고서는 유지합니다. 합성 반복 수치와 Gate는 이 탭에만 표시하며 실제 프로젝트 1의 5회 실행 결과로 합산하지 않습니다.

## 조회 API와 보호

- `GET /api/recorded-reviews`: 유효한 이름·경로의 최근 저장 기록 최대 100개.
- `GET /api/recorded-reviews/{report_id}`: 사례·역할·근거의 허용 필드만 반환.
- 기존 `/api/runs`, 단계·Artifact·정적 보고서 API는 평가기 자체 검증용으로 유지.
- 저장 기록 이름·경로·파일 크기·집계·근거 연결을 검사합니다. 링크를 통한 외부 파일 조회를 차단합니다.
- 알려진 비밀정보·로컬 절대경로 패턴을 숨기고 HTML 문자를 이스케이프합니다. 모든 종류의 민감정보 탐지를 보장하지는 않습니다.
- 색상과 상태 문구를 함께 쓰며 좁은 화면에서는 비교 표 안에서만 가로 스크롤합니다.

## 전체 실행 기록 탭

`FLOW-...` 기록의 회차별 A1~4 수행 상태·코드 검사·Judge 상태를 조회합니다. TEST_DOUBLE은 무과금 연결 검증, FULL_FLOW_PILOT은 실제 모델 파일럿으로 구분합니다. 무과금 기록을 실제 성능에 합산하지 않습니다. 중간 차단으로 A3/A4가 실행되지 않으면 미실행으로 표시하며 ‘수행 완료’는 품질 합격이 아닙니다.

`GET /api/full-flows`와 `GET /api/full-flows/{flow_id}`는 허용된 요약만 반환하며 작업 폴더·압축 증거를 웹으로 제공하지 않습니다. 화면에서 API 실행을 시작하는 기능은 없습니다.

## 남은 범위

이전 P1 버전에서 기존 TC 재사용·실제 시험·A4 보고까지 완료한 기록이 있지만 별도 Judge는 오류로 중단됐습니다. 2026-10-23 대표 5개 전체 실행과 채점, 사람 대조(누적 27개)는 진행했습니다. 같은 버전 반복 측정(대표 5개 × 3회)과 의미 일관성 판정은 남아 있습니다. 호출 한도로 재작성을 중단한 회차는 ‘호출 한도 중단’으로 표시하고 원본 ERROR 상태도 별도 필드로 보존합니다. 이 표시가 앞선 CP 위반을 통과로 바꾸지는 않습니다. 독립 `JUDGE-...` 기록 전체를 합치는 기능도 없습니다. [최신 검증 상태](../PROJECT_HANDOFF.md)를 따릅니다.
