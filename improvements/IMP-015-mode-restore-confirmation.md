## 문제와 영향

H-6 온도 요청서(냉방 하한 19°C, 난방 16°C 적용)에서 TC는 준비 단계에서 모드를 냉방 또는 난방으로 바꾼 뒤 설정 온도를 시험합니다. 시험 후 복원 절차에는 "모드와 온도를 준비 전으로 되돌린다"는 조작이 있지만, **확인 문장과 비교 항목은 설정 온도(패널·카드·내부값)만** 있습니다. 사람이 TC 문서만 보고 실행하면 모드가 원래대로 돌아왔는지 확인하지 않고 끝날 수 있습니다.

- 실제 실행기는 영향 없음: 실행 단계의 `RESTORE_OBSERVED_CONTROLLER`가 준비 전 전체 상태와 비교하므로 실제 복원 여부는 검증됩니다.
- 문제는 **사람이 읽는 TC 문서와 그 계약**에 있습니다. P1의 검토 AI와 CP2는 이를 통과시켰고, P2 채점과 코드 대조가 찾아냈습니다.
- 같은 조건의 전원·풍량·모드 시나리오에서는 나오지 않았습니다(바꾼 값 자체가 시험 대상 ER이라 복원 확인이 연결됨).

## 원인과 수정

**확인된 원인(구조적):**

1. Agent 2 규칙 29는 "준비와 시험으로 바뀐 관제점을 복원"하라고 이미 요구합니다. 그래서 복원 조작 문장에는 모드가 들어갑니다.
2. 규칙 30과 CP2 계약(`_structured_restoration_errors`)은 복원 확인(confirmations)이 **관찰 위치가 있는 기존 상태 ER만** 참조하도록 강제합니다("복원 확인은 관찰 위치가 있는 기존 상태 ER만 참조할 수 있습니다").
3. 모드는 준비 단계에서만 바뀌므로 시험 결과 ER이 없습니다. 규칙 20은 준비 확인을 제품 ER로 만들지 못하게 합니다.
4. 따라서 모델이 모드 복원 확인을 쓰고 싶어도 **계약상 연결할 대상이 없습니다.** 모델 판단 실수가 아니라 계약이 표현할 수 없는 구조입니다.

**수정 방향(2026-10-24 사용자 결정: A안 적용):**

- A안(권장): 복원 확인이 기존 ER 외에 **준비 확인(`precondition_verifications`)도 참조**할 수 있게 계약을 넓히고, 준비에서 바꾼 상태마다 복원 확인을 요구합니다. 변경: `qa_pipeline_contracts.py` 복원 계약, CP2 복원 검사, Agent 2 규칙 30·31, 관련 시험.
- B안: 수정하지 않고 "실행기는 전체 비교, TC 문서는 시험 ER만"이라는 한계로 문서화합니다.

수정 전 "작성 지침 한 줄 추가"로 정했던 계획은 이 원인 때문에 계약 수정이 함께 필요합니다.
