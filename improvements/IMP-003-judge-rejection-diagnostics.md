## 확인한 사실

### 2026-09-25 새 실제 실행

`FLOW-20260925-055923-9ce62a`에서 P1의 재사용 실행·A4 보고는 완료됐지만, 첫 A1 Judge가 `UNVERIFIED_QUOTE`로 거절됐습니다. 이번에는 받은 응답과 안전한 진단 코드가 보존되어 원인을 확인했습니다. C01에서 원문의 서로 다른 SRS 표 행을 한 문장처럼 합쳐 인용했고, A1-03에서는 JSON 배열 값을 쉼표 문장으로 다시 쓴 인용을 반환했습니다. 원문 위치의 실제 내용과 일치하지 않으므로 현재 검사에서 거절한 것은 확인됩니다. 이 오류만으로 모델의 모든 평가 의견이 틀렸다고 판정하지 않습니다.

인용을 연속 원문 그대로 반환하고 배열은 원소 경로를 지정하도록 안내하는 최소 보완을 제안합니다. 문자열 검사를 느슨하게 하거나 거절 응답을 수작업으로 합격시키지 않습니다. 이 지침 변경과 새 실제 호출은 아직 하지 않았습니다. A2에는 별도로 전송 자료 크기 초과가 있었고 실제 호출되지 않았습니다. 호출 수·완료 범위·다음 순서는 [최신 인계](../PROJECT_HANDOFF.md)에 기록합니다.

### 이전 실행 · 정확한 원인 미확정

P1 재사용 흐름과 CP4는 완료됐지만 첫 A1 Judge가 ERROR/INCOMPLETE로 종료했습니다. SDK 평가 호출은 1회이며 응답 ID·서버 completed·사용 토큰 19,865가 기록돼 있습니다. response_received=true, structured_response_valid=false, error_type=ValueError, judgments=[]입니다. 불확실한 평가를 합격으로 사용하지 않았습니다.

당시 openai_judge.evaluate는 응답을 받은 뒤 validate_judgment로 평가 항목·근거 경로·인용 등을 검사했습니다. 실패하면 민감한 SDK 메시지가 노출되지 않도록 예외 종류만 기록했습니다. 거부된 구조화 응답과 내부 판정 이유는 따로 남지 않아 과거 ValueError가 어느 항목·근거에서 발생했는지 저장 파일만으로 확정할 수 없습니다. 원인을 인용 오류로 단정하지 않습니다.

## 2026-09-25 적용한 최소 보완

1. 내부 검증 거부에 안전한 오류 코드와 항목 인덱스를 기록합니다. SDK 예외 전문·키·요청 헤더는 기록하지 않습니다.
2. 받은 구조화 응답은 120,000바이트 한도와 기존 민감정보 검사를 통과한 경우에만 `received_response.json`으로 보존하고 해시를 남깁니다. 안전하게 보존할 수 없으면 제외 사유만 기록하고 중단합니다. 이 파일은 검증 전 진단 자료이며 유효한 `judgments`가 아닙니다.
3. 인용 불일치·잘못된 경로·항목 누락 및 민감정보·과대 응답을 Fake Client로 검사했습니다. 최신 전체 검사 결과는 [인계 문서](../PROJECT_HANDOFF.md)에 둡니다.
4. 기존 근거 검사와 안전 중단을 유지합니다. 과거 기록은 성공으로 바꾸지 않고 자동 재시도도 추가하지 않았습니다. 과거 미보존 응답은 복원할 수 없으며 새 실제 호출은 별도 승인이 필요합니다.

2026-09-20 실행에서도 P1 완료는 확인됐지만 별도 모델의 의미 평가는 미완료였습니다. 당시 A2·A3·A4 Judge는 안전 중단으로 미실행이며 5회 일관성·평가자 교정도 수행하지 않았습니다. 새 실행의 미평가 사유는 위의 2026-09-25 절과 최신 인계 문서를 따릅니다.
