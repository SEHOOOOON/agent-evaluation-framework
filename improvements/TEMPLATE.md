## 날짜별 개선 기록

날짜는 한국 시간으로 적습니다. 수정과 검증 날짜가 다르면 행을 나누고, 확인되지 않은 과거 날짜는 추정하지 않습니다. 아래 표는 모든 개선의 필수 요약입니다.

| 수정일 / 검증일 | 수정 전 내용 | 수정 후 내용 | 수정 후 정상 여부·근거 | 부작용·남은 확인 |
|---|---|---|---|---|
| YYYY-MM-DD / 미검증 | 실제 문제와 이전 동작 | 변경 파일과 바뀐 동작 | 미검증 또는 로컬·저장 자료·실제 API 검증의 결과와 증거 링크 | 확인 범위와 미검증 항목 |

후속 검증은 날짜와 결과를 추가합니다. 실패한 검사와 이전 실행 기록도 보존합니다.

## 문제와 영향

요청한 동작과 실제 출력을 비교합니다.

## 원인과 수정

확인된 원인과 가설, 수정 전·후 동작, 변경 파일, 유지할 기준을 기록합니다.

## 비교 조건

- 수정 전·후 커밋 / 파일 해시:
- 요청·SRS·공식 TC / 모델·작성 지침:
- 평가 기준·정답 검토 상태 / 생성·평가 호출 한도:
- 비교 조건 차이와 해석 제한:

## 검증 결과

- 로컬 회귀·정상/실패 반례:
- 실제 실행 ID / SDK·HTTP·정상 응답 수:
- 최초 출력·재작성 / 역할별 도달·미실행·해당 없음:
- 원본·공식 자산 보존 / 새로 발견한 문제:

## 결론과 포트폴리오 설명

확인한 개선과 남은 한계를 함께 설명합니다. 자동 테스트 개수를 Agent 품질 점수로 표현하지 않습니다.
