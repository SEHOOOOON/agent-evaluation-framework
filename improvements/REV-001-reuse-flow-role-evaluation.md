# REV-001 · 기존 TC 재사용 실행의 역할별 평가

## 평가 대상과 읽는 방법

프로젝트 1 고정 버전 `d01e203`의 `RUN-20260925-055924-A422BA`를 평가했습니다. 새 TC·자동화 계획을 생성하지 않고 기존 MED/HIGH TC를 실행한 경로입니다. 프로젝트 1을 다시 실행하거나 평가를 통과시키기 위해 공식 자산을 수정하지 않았습니다.

동일 실행의 저장 산출물에 대한 후속 역할 평가를 모은 기록입니다. 원래 전체 실행 평가가 중단된 기록은 그대로 보존합니다. A1은 `openai-judge-1.4`, A2~4는 `1.5`이며 모두 `gpt-5.6-terra`, `role-rubric-2.1`을 사용했습니다. 같은 평가기 버전의 연속 전체 실행이나 반복 일관성 시험으로 해석하지 않습니다. 실제 횟수·토큰·원본 결과 위치는 [인계 문서](../PROJECT_HANDOFF.md)에 있습니다.

모델 판정과 아래 Codex 원문 대조를 구분합니다. 후속 대조는 사람 승인 정답이 아니며 저장된 모델 FAIL을 PASS로 덮어쓰지 않습니다.

## 역할별 결론

| 역할 | 모델 평가와 확인 범위 | 원문 대조 및 남은 한계 |
|---|---|---|
| Agent 1 · 분석 | 변경·유지 범위, 값, 근거 연결 기준에서 PASS | 이 입력 한 건의 평가이며 다른 요구사항·미정 조건·충돌 지시 대응까지 검증한 것은 아님 |
| Agent 2 · 설계·재사용 | TC 재사용 및 조작 순서는 PASS, HIGH TC의 복원 성공 확인 설명은 FAIL | HIGH는 기존 공식 자산이며 이번에 생성한 TC가 아님. Agent 2는 LOW 시작·복원 실제 수행 확인을 최종 검토로 전달했음. 명세 부족과 Agent의 처리 책임을 별도로 판단해야 함 |
| Agent 3 · 자동화·실행 | 신규 계획·UI 선택·코드 생성 기준은 해당 없음. 실행 연결은 확인되지만 복원 증거는 REVIEW | 실제 실행 요약·파일 경로·해시만으로 모든 복원 관찰값을 읽을 수 없음. 평가 자료 부족이며 실제 실행 실패로 단정하지 않음 |
| Agent 4 · 규칙 기반 보고 | 집계·연결은 PASS, 미확인 사항 후속 안내는 FAIL | 원본 JSON과 사람 검토서에 해당 안내가 보존됨. 이 FAIL 이유는 원문과 모순됨. 전부 통과한 실행이므로 실패 원인 분류 정확도는 미검증 |

## 발견 사항의 책임 구분

### 1. 기존 자산의 부족 · HIGH TC

`TC-V2-001`의 명세에는 LOW 복원 조작만 있고 성공 확인 방법이 없습니다. 실제 실행 코드의 해시를 승인 코드와 대조했으며, 화면 복원 비교는 있지만 내부 `fanSpeed` 복원 비교는 없습니다. MED `TC-V2-002`는 화면·내부값 복원 비교를 모두 포함합니다.

Agent 2는 두 기존 TC의 LOW 시작·복원 수행 여부를 사람이 확인하도록 남겼고, 이 안내는 최종 보고까지 보존됐습니다. 따라서 ‘부족을 전혀 처리하지 않았다’고 단정할 수는 없습니다. 다만 이 일반적인 확인 안내가 HIGH의 구체적 확인 누락을 충분히 다룬 것인지는 사람 검토가 필요합니다. 재사용 판단 PASS와 상세 복원 명세 FAIL은 다른 질문이며 단순 평균으로 합치지 않습니다.

### 2. 평가 자료의 부족 · Agent 3

이번 평가 입력의 `compiled_code`는 비어 있고 실행 요약과 증거 파일 정보가 제공됐습니다. 신규 계획이 없는 분기 자체는 정상입니다. 그러나 기존 자동화 코드의 복원 확인 범위와 실제 관찰 내용을 모델이 직접 읽은 것은 아닙니다.

후속 로컬 대조에서는 실행 코드 지문·원본 증거 파일 지문·성공 로그를 확인했습니다. 이것은 평가 모델의 REVIEW를 자동 해제하거나 모든 내부 복원을 검증했다는 뜻이 아닙니다. 다음 증거 보완 후보는 기존 실행 코드의 관련 부분과 해당 실행의 시작·복원 관찰 내용입니다. 이번에는 자료 수집기나 평가 지침을 수정하지 않았습니다.

### 3. 평가자의 해석 문제 · Agent 4

모델은 `recommendation=PASS`, `검토_항목=[]`와 상위 단계의 확인 사항을 근거로 ‘구체적 후속 검토를 제시하지 않았다’고 판단했습니다. 하지만:

- 최종 보고의 `최종_확인_사항`에는 CP1·CP2 및 LOW 시작·복원 증거 확인 안내가 남아 있습니다.
- 평가 입력에서 해당 필드는 `evidence_reference`로 같은 내용의 위치를 가리키며, 참조를 풀면 원본 보고와 같습니다.
- 사람 검토서의 ‘추가 확인 사항’ 절에도 안내가 그대로 표시됩니다. 자동 실행 판정과 공식 SRS·TC 승인이 별개임을 명시합니다.

따라서 이번 FAIL의 ‘후속 안내 누락’ 주장은 채택하지 않습니다. `검토_항목`은 실행 결과에서 분류된 항목이며 모든 사람 확인 사항을 담는 유일한 필드가 아닙니다. 참조 표시나 PASS 의미를 혼동했을 가능성이 있지만, 모델 내부 원인을 확정하지 않습니다. 원본 모델 결과와 이 반증을 함께 보존합니다.

### 4. 아직 시험하지 않은 범위

모든 제품 실행이 통과했으므로 Agent 4가 실패 원인을 정확히 분류하는지는 확인할 수 없습니다. 모델의 A4-02 PASS는 이번 자료의 환경·제품 구분에 한정하며 원인 분류 성능 점수로 사용하지 않습니다. 새 Agent 3 계획 생성·재작성·기대결과 보존, 새 실패 사례, 사람 승인 후 등록, 같은 조건 반복 일관성도 이번 실행만으로 완료되지 않습니다.

## 후속 순서

1. 위 발견 사항의 귀속과 미평가 범위를 사람이 검토합니다. 점수를 높이기 위한 P1 수정은 하지 않습니다.
2. 기존 증거에서 시작·복원 관찰을 확인할 수 있는지 먼저 살펴봅니다. 근거가 없다면 새 실행 필요 범위로 남깁니다.
3. 별도 승인 후 신규 계획 경로 및 실제 실패 사례를 평가해 이번에 관찰하지 못한 역할을 확인합니다.

이번 작업에서는 추가 검사 분기·TC별 예외·판정 자동 보정·공식 자산 수정·커밋·푸시를 하지 않았습니다. 네 역할 결과를 확보한 것과 프로젝트 1 전체 품질 검증 완료는 다릅니다.
