- 발견일: 2026-10-09 (한국 시간)
- 대상: P2의 반복 실행 관리·결과 집계·근거 표시. P1의 생성·실행·승인 기준 변경 아님.

### 제출 전 후속 근거

- 공통 집계/표시만 수정: `src/eval_harness/local_stability.py`, 기존 `tests/test_local_stability.py`의 반례 검증 보강. 파일·해시 대조 기준은 완화하지 않았다.
- 종합 점수 집계는 수정 전에도 ERROR/NOT_RUN을 제외했다. 이번 결함은 브라우저·복원 횟수, 시나리오별 결과 요약과 개별 행의 확인/통과 표시에 있었다. 저장된 실제 100회에 근거 오류가 발견됐다는 뜻은 아니며, 손상시킨 시험용 반례에서 재현했다.
- 전체 회귀: `evaluation-runs/transfer-final-20261005/submission-final/{tests.xml,regression.json}`. 851 PASS, 실패/오류/skip 0, 104.720초, API·외부 Python 연결 시도 0, 검사 중 평가 소스 불변.
- 이후 집계 테스트의 확인문만 보강해 유효한 예상 밖 결과(MISMATCH) 2건도 실행·복원 횟수에 남고, 숫자 1을 실행 여부 true로 세거나 복원 실패를 성공으로 세지 않음을 확인했다. 런타임 코드는 그대로이며 해당 17개 모두 PASS(`final-submit-20261009/p2-summary-final.xml`). 851개와 중복 합산하지 않는다.
- 수정 전 반례 및 저장 100회 재집계: 형제 P1 `runs/manual_checks/final-submit-20261009/{p2-summary-before.xml,submission-check.json}`. 해당 폴더의 시작/종료 해시로 이번 수정과 기존 사용자 변경을 구분한다. 원본 100회 파일/보고서·과거 점수는 덮어쓰지 않았다.
- README 첫 화면 설명, 평가 계획의 구현된 E02/E03/E04 범위, 세부 기준의 현재 재사용 A3-03 REVIEW/2.5 패킷 설명도 코드에 맞췄다. 평가 기준을 수정한 것이 아니다. 관련 기준/경계/관찰 293개 검사 PASS(`submission-docs/tests.xml`); 전체 851개와 합산하지 않는다.
- 같은 날 과거 `scripts/check_full_flow_offline.py`의 “현재 P1 재생” 설명을 정정했다. 생성 응답 3종만 연결해 현재 별도 검토 응답을 제공할 수 없고, 기본 CLI/현재 회귀에서는 사용하지 않는 참고용 도구다. 런타임 동작은 바꾸지 않았으며 미지원 기능을 새로 구현하지 않았다. 모듈 설명을 제외한 Python AST가 수정 전 백업과 같음을 확인했다. 이 도구로 최신 전체 재생이 성공했다고 주장하지 않는다.

## 문제와 영향

제품이 요구한 대로 동작하지 않아 FAIL이 나온 경우와, 파이프라인이 엉뚱하게 처리한 경우는 다르다. 또한 100회가 같은 AI를 100번 새로 호출한 것인지, 저장된 TC를 반복 실행한 것인지 구분하지 않으면 숫자가 실제보다 크게 해석된다.

## 원인과 수정

- `scripts/run_local_stability.py`: 다섯 관제점·제품 불일치·실행 제외·질문 대기·저장 TC·등록 TC 재사용·사본 자산 선택을 20개 시나리오로 준비한다. 이번 요청은 각 5회다. 새 시나리오별 제품 예외나 AI 검토 기준은 추가하지 않는다.
- `src/eval_harness/local_stability.py`: 사전 기대결과와 회차 기록·근거 파일 해시를 대조한다. 누락은 미실행으로 분모에 남기고, 같은 오답이 반복되는 경우도 일관성과 정확성을 분리한다. 기록 JSON의 주장과 실제 저장 facts/grades가 다르면 오류로 표시한다.
- 같은 기록을 기존 `A3-03`, `A4-01`, `A4-03` 검사에 연결한다. 나머지 항목에 임의의 점수를 채우거나 기존 AI 평가와 합산하지 않는다. 제품 처리 일치와 P2 위반도 별도로 표시한다.
- HTML 표는 시나리오 요약·회차별 근거·문제만 보기·26항목별 이번 확인 범위로 구성한다. 기존 포폴 디자인은 바꾸지 않는다.

## 비교 조건

- P1 현재 작업본 HEAD `3871164`, P2 HEAD `1559aab`에 각각 기존 미커밋 변경이 있어 커밋만으로 동일성 판단하지 않는다. 실제 실행 고정 해시는 `evaluation-runs/l1009/frozen.json`에 저장한다.
- P1 코드·제품·공식 TC·SRS·과거 Run은 읽기 전용. 자산 선택은 독립 사본에서 함수 호출하며 실제 승인 UI 조작·공식 등록이 아니다.
- 입력은 사람이 준비한 공통 TC, 실제 저장 냉방→제습 분석/TC/검토, 실제 정보 부족 분석, 등록 HIGH TC 유지보수 자료로 구분한다. 새 요구사항 분석·생성·의미 검토는 수행하지 않는다.
- API 0회. Python 외부 연결 및 브라우저 외부 요청을 막고 서비스 환경변수를 제거한다. OS 보안 격리를 제공한다고 주장하지 않는다.

## 검증 결과와 보존한 실패

- 사전 점검 `l1009-pre`: 20개 예정 중 13개 예상 처리, 14번째 보류 경로에서 시험 스크립트 오류로 중단, 6개 미실행. P1은 PAUSE 상태에서 다음 단계를 정상 차단했으나 스크립트가 오류 문구를 기대했다. P1 검사는 바꾸지 않고 저장 상태·질문·차단 사실로 확인하도록 시험 스크립트를 수정했다.
- 사전 재검사 `l1009-pre2`: 보류·재사용·자산 선택 7개 모두 예상 처리. 두 사전 검사 기록은 본 100회에 합산하지 않는다.
- 집계기 포함 초기 전체 회귀: `evaluation-runs/transfer-final-20261005/local100-full/`의 836 PASS, 실패·오류·skip 0. P1 실행 횟수와 별개다.
- 본 100회: `evaluation-runs/l1009/`에서 100/100 예상 처리·제품 PASS 60·제품 불일치 검출 5·비제품 경로 35, 각 시나리오 5회 일치. 제품 브라우저 시험 65회 모두 복원 기록을 확인했다. 후속 평가/화면 검수는 `evaluation-runs/l1009-review/`, 최신 실행 범위는 인계 문서에 기록했다.
- 후속 보완 포함 전체 회귀 851 PASS, 원본 100회 보존 확인. 데스크톱/모바일에서 100행·20종·26기준·필터·연결 파일·JS 오류 및 화면 가로 넘침을 검수했다. 이전 836개와 중복 합산하지 않는다.
- 실행 도중 발견한 P2의 과거 후보 로그만 대조하는 문제는 [IMP-005](IMP-005-p1-contract-compatibility.md)의 후속 보완으로 관리한다. 본 실행 코드·기준은 중간에 바꾸지 않는다.

## 부작용과 남은 한계

- 자료가 없는 새 Git 복제본에서는 이 시나리오 묶음을 그대로 실행할 수 없다. 로컬 원본을 예시 데이터로 꾸며 채우지 않는다.
- 각 시험은 독립 환경에서 시작한다. 장시간 같은 세션에 누적되는 문제·동시 승인·프로세스 강제 종료·실장비·Slack/Notion 수신은 이번 대상이 아니다.
- 정상으로 준비한 TC 반복은 AI가 다양한 문장에서 같은 TC를 만들 수 있다는 증거가 아니다. 모델의 해석·검토 정확성은 기존 26항목과 사람 정답 대조 안에서 별도 확인이 필요하다.
- 복원 횟수는 실행기 기록 기준이며 모든 화면·내부 상태를 독립 측정한 별도 장치가 아니다. P2 A3-03 점수도 복원 전체 점수가 아니다.
