## 기록 원칙

- [IMP-006 · 포트폴리오 평가·실행 근거 분리](IMP-006-portfolio-evidence-presentation.md): 2026-10-04 로컬 페이지 추가. 원본 26항목, 자산관리 70건, 개선·미검증 범위를 구분하며 새 평가 결과로 세지 않는다.

2026-10-03 사용자 요청에 따라 모든 개선에 **날짜·수정 전·수정 후·수정 후 정상 여부와 근거**를 필수로 기록합니다. 수정일과 검증일을 구분하고 미실행은 `미검증`으로 남깁니다. 기존 이슈는 같은 파일에 후속 날짜를 추가하며 [작업 규칙](../AGENTS.md)과 [기록 양식](TEMPLATE.md)을 따릅니다.

- [IMP-005 · P1 산출물과 평가 계약 정합성](IMP-005-p1-contract-compatibility.md): 결합 인용·결정론적 A3 연결·실행 전체 근거 부족 보고를 P2에 반영. 10월 5일 역할별 파일 전달·기존 TC 목록·사람 검토서·root/nested 비교 누락을 대조하고 수집기를 보완했다. 저장 자료/로컬 검증이며 새 모델 평가가 아님.

역할별 결과를 종합할 때는 [REV-001 · 기존 TC 재사용 실행 평가](REV-001-reuse-flow-role-evaluation.md)를 참고합니다. 프로젝트 1의 처리 문제, 기존 자산 부족, 평가 입력 부족, 평가자 오판을 구분하며 발견 즉시 P1 수정으로 연결하지 않습니다.

- [IMP-004 · 평가 이유의 과잉 해석 구분](IMP-004-judge-interpretation-boundaries.md): 전원 사례 A3의 복원 확인 오반려와 A4의 적용 범위는 후속 응답에서 개선 확인. A2 TC-R05 비적용 오판은 2026-10-03 재평가에서도 미해결이며 후속 2.4 안내 정리는 로컬 검증만 완료했다. 서로 다른 평가 버전의 평균 집계는 로컬 검증 완료. 날짜별 전후 상태와 근거는 해당 기록 참조.

- 발견 실행·원본 증거·검출 주체를 기록합니다. P1 Checkpoint와 P2 코드 검사·AI Judge·사람 검토를 구분합니다.
- 증상, 확인된 원인, 수정 파일, 유지할 기대값·검사를 연결합니다.
- 수정 전·후 소스 커밋과 입력·모델·평가 기준·호출 예산 차이를 남깁니다.
- 원본은 보존하고 후속 실행을 별도 연결합니다. 미실행을 성공으로 세지 않습니다.
- 한 번의 성공으로 반복 일관성이나 전체 품질 합격을 주장하지 않습니다.
- 새 문제는 기존 문제의 재발과 구분해 기록합니다. 외부 공개는 별도 승인 후 진행합니다.

## P2에서 발견한 문제를 개선할 때마다 따르는 절차 (2026-10-24)

P2 채점·코드 대조·사람 대조에서 P1 문제가 나오면 **사례마다 보고서 1개**를 이 폴더에 남깁니다. 새 기록 위치는 만들지 않고 아래 순서를 따릅니다.

1. **발견 즉시 기록:** 다음 번호로 `IMP-XXX-짧은-이름.md`를 [기록 양식](TEMPLATE.md)으로 만들고 위 목록에 한 줄 추가합니다. 상태는 `발견`. 실행 ID·원본 경로·검출 주체(P2 AI 채점 / P2 코드 대조 / 사람)를 적습니다.
2. **맞는 감점인지 확인:** 사람 대조 또는 원본 확인으로 평가자 오판이 아닌지 정합니다. 오판이면 P2 쪽 수정 사례로 기록하고 P1은 고치지 않습니다.
3. **재발 확인:** 한 번만 나온 문제는 반복 실행이나 저장 자료로 재발 여부를 먼저 봅니다. 횟수(예: 4번 중 4번)를 표에 남깁니다.
4. **원인 조사:** 모델 판단, 작성 지침, 계약·검사 코드 중 어디가 원인인지 파일과 줄을 적습니다. 지침만으로 고칠 수 없으면 그 이유를 적습니다.
5. **수정 방향 결정:** 선택지가 있으면 사용자 결정을 받은 뒤 적용합니다. 결정 전 상태는 `결정 대기`.
6. **수정과 로컬 검증:** P1 수정 커밋, 로컬 시험 결과를 날짜별 표에 한 행으로 추가합니다(수정 전·후·근거).
7. **실제 재검증:** 비용을 먼저 안내하고 승인 후 실행합니다. 합격 기준을 실행 전에 보고서에 적고, 결과(실행 ID·통과 횟수)를 표에 추가합니다. 미실행은 `미검증`으로 둡니다.
8. **마감:** 결론에 확인한 개선과 남은 한계를 적고, 목록의 확인 수준을 갱신합니다. 이전 행은 지우지 않습니다.

새 사례에는 [기록 양식](TEMPLATE.md)을 사용합니다. 상태는 발견 → 결정 대기 → 수정 → 로컬 검증 → 실제 재평가 → 한정된 개선 확인 또는 미해결로 관리합니다.
