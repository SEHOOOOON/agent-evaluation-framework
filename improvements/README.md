# 평가 기반 개선 이력

프로젝트 2에서 확인한 문제를 프로젝트 1의 수정과 재평가 증거에 연결합니다. 이전 실패 기록은 수정하지 않으며 자동 테스트, 저장 자료 재검사, 실제 모델 실행을 구분합니다.

| ID | 문제 | 수정 | 확인 수준 |
|---|---|---|---|
| [IMP-001](IMP-001-redundant-srs-revision.md) | 이미 반영된 SRS에 동일한 수정안 제출 | P1 작성 지침·개정 검사 보완 | 실제 응답 1건에서 개선 확인 / 전체 흐름은 다른 문제로 중단 |
| [IMP-002](IMP-002-compound-condition-links.md) | 복합 조건을 선택한 TC 전체에 연결하지 않음 | 작성 지침·읽기 전용 연결 진단 보완 | 실제 연결·TC 실행·CP4 통과 1건 / Judge 평가 미완료 |
| [IMP-003](IMP-003-judge-rejection-diagnostics.md) | 평가 모델 응답 거부 시 상세 진단 근거 미보존 | 원인 확정 및 안전한 진단 기록 보완 필요 | P2 Judge ERROR / 미해결 |

## 기록 원칙

- 발견 실행·원본 증거·검출 주체를 기록합니다. P1 Checkpoint와 P2 코드 검사·AI Judge·사람 검토를 구분합니다.
- 증상, 확인된 원인, 수정 파일, 유지할 기대값·검사를 연결합니다.
- 수정 전·후 소스 커밋과 입력·모델·평가 기준·호출 예산 차이를 남깁니다.
- 원본은 보존하고 후속 실행을 별도 연결합니다. 미실행을 성공으로 세지 않습니다.
- 한 번의 성공으로 반복 일관성이나 전체 품질 합격을 주장하지 않습니다.
- 새 문제는 기존 문제의 재발과 구분해 기록합니다. 외부 공개는 별도 승인 후 진행합니다.

새 사례에는 [기록 양식](TEMPLATE.md)을 사용합니다. 상태는 발견 → 수정 → 로컬 검증 → 실제 재평가 → 한정된 개선 확인 또는 미해결로 관리합니다.
