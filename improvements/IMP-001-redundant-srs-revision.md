- P1 사본 Run: RUN-20260920-084032-63DBCD
- 원본 증거: 위 실행 폴더의 trial-1/evidence.zip. [중단 초안 패킷](../evaluation-runs/FLOW-20260920-084030-a2f592/post-review/A2/packet.json)은 후속 조회 자료입니다.
- 검출 주체: **P2가 실행·수집한 P1 CP2 차단과 후속 코드 검토**. 당시 별도 AI Judge는 0회였으므로 평가 모델이 독립적으로 발견했다고 표현하지 않습니다.

## 1. 무엇이 문제였나

현재 SRS에는 이미 MED의 중풍 표시와 HIGH의 강풍 표시가 있었습니다. Agent 2는 공식 TC 두 개를 재사용하기로 선택했지만 현재와 동일한 문장을 SRS 수정안으로 제출했습니다. 실제 문서 변경이 없는데 다시 승인을 요구하는 결과였습니다.

CP2는 동일한 전·후 문장을 차단했습니다. 생성 호출 3회를 소진해 재작성·후속 시험을 수행하지 못했습니다. A1 최초·재작성 2회와 A2 최초 1회이며 전체 흐름을 3회 실행한 것이 아닙니다.

## 2. 원인과 수정

모델 출력뿐 아니라 MODIFIED·UPDATE_REQUIRED에는 항상 개정안을 요구하던 작성 지침·검사가 원인이었습니다. 동시에 같은 문장은 개정으로 인정하지 않아 규칙이 충돌했습니다.

| 상황 | 수정 전 | 수정 후 |
|---|---|---|
| 요청 after_value 전체가 현재 인수 기준과 같음 | 개정안 강제 | 해당 대상 개정 불필요, TC 검증 계속 |
| 실제 기준 변경이 필요함 | 근거 있는 개정안 필요 | 유지 |
| 동일 문장 또는 불필요한 재표현으로 수정안 제출 | 동일 문장 차단 | 계속 차단하고 개정안 제외 안내 |
| 일부만 같거나 비슷한 표현 | 개정 요구 | 자동 생략하지 않음 |

코드가 계산한 개정 범위를 모델 입력과 검사기가 공유합니다. 앞뒤 공백을 제외한 전체 문장 비교이며 특정 풍량·TC ID에 고정하지 않습니다. 다른 영향 Requirement의 개정 요구·시험 범위·기대값·사람 승인 경계는 유지합니다.

변경 파일: P1의 src/qa_pipeline_agent2.py, src/qa_pipeline_execution.py, 관련 테스트 2개와 문서 5개. 공식 SRS·TC·제품·기존 Run은 변경하지 않았습니다.
