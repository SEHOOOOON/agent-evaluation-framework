# 사용자 TC 기준 정답지 · 상세도와 작성 형식

버전: 1.1 · 지정일: 2026-09-19 · 범위 변경 규칙 추가: 2026-10-15

사용자가 제공한 TC를 기준 정답지로 지정하도록 명시적으로 요청했습니다. 새 예시를 요구하지 않고 기존 제공 자료를 기준으로 사용합니다. 이 지정은 아래 개별 생성 TC의 검토 결과를 사용자가 승인했다는 뜻이 아닙니다.

## 원본과 적용 범위

- 사용자 첨부 이미지 1: 실내기 설정온도, 풍량, 풍향 자동 TC.
- 사용자 첨부 이미지 2: 장비 선택, 운전/정지, 모드 변경, 공기청정 TC.
- 대화에 제공된 이미지에서 확인한 구조를 정리한 문서입니다. 전체 엑셀 원본을 확보했거나 잘린 셀을 모두 전사했다고 주장하지 않습니다.
- 원본의 강점은 번호가 붙은 조작 순서, 단계에 대응하는 기대결과, 제어 패널과 장비 카드의 구분, 구체적인 값·상태, 경계 입력의 명시입니다.
- 온도 예시의 18/30도, 모드별 색상, 버튼 클릭 횟수, 시뮬레이터 명령은 해당 예시의 맥락입니다. 다른 요구사항에 복사하는 공통 정답이 아닙니다.

## 기준 항목

| ID | 합격 기준 | 보완이 필요한 경우 |
|---|---|---|
| TC-R01 | 대상·시작 상태·필요한 준비가 명확함 | 대상 장비나 시작값을 추측해야 함 |
| TC-R02 | 선택·설정·적용 순서를 따라 재현 가능함 | 여러 조작이 뭉쳐져 무엇을 먼저 할지 모호함 |
| TC-R03 | 판정할 조작에 기대결과가 연결됨 | 언제 결과를 확인하는지 알 수 없음 |
| TC-R04 | 확인 위치와 관찰할 값·상태가 구체적임 | '정상 동작', '결과와 일치'만 있고 판정 기준이 없음 |
| TC-R05 | 요구사항이 정한 경계·허용·차단 조건을 검증함 | 범위 요구인데 정상값만 확인함 |
| TC-R06 | 상세함을 위해 요구사항 밖 기대값을 추가하지 않음 | 근거 없는 색상·알림·상태를 정답으로 단정함 |

준비 동작마다 제품 기대결과를 억지로 추가하지 않습니다. 모든 TC에 온도 경계나 화면/내부 이중 검증을 강요하지 않고, 해당 요구사항에 필요한 항목만 적용합니다. 문장 수·길이·특정 단어 포함만으로 상세도 합격을 판정하지 않습니다.

## 프로젝트의 추가 기준

TC-R07: 상태를 변경하는 시험은 복원 절차와 복원 성공 확인을 명시합니다. 이는 기존 V2의 독립 실행·복원 계약을 함께 적용한 기준이며, 제공 이미지 전체에 복원 절차가 있었다고 주장하지 않습니다.

## 허용 범위 변경 요청의 확정 규칙 (사람 판단, 2026-10-15)

2026-10-15 실제 실행(FLOW-20261015-110607-bb73a2)을 사람이 대조해 검토 AI·P2 채점이 모두 통과시킨 오답 3개(새 상한+1 차단 누락, 새 하한 적용의 별도 기대결과 없음, 범위 밖 기존 온도에서의 모드 전환 동작 미질문)를 확인했습니다. 아래는 그때 사용자가 확정한 규칙이며 새 기준 ID가 아니라 기존 TC-R03~R06의 판정 기준을 구체화한 것입니다. L·U는 현재 요청/SRS가 정한 **바뀐 모드**의 새 하한·상한이며 값은 요청마다 다릅니다. P1 `QA_RANGE_CHANGE_RULES`와 같은 내용입니다.

| 규칙 | 내용 | 연결 기준 | 예시 (요청이 "모드 M의 범위를 L~U로 변경"일 때) |
|---|---|---|---|
| T-1 | 바뀐 모드의 L 적용과 U 적용을 각각 별도 기대결과로 확인 | TC-R03·R05 | "L 적용 → 패널·카드·내부값 L" 과 "U 적용 → … U"가 따로 있어야 함 |
| T-2 | 바뀐 모드의 L-1·U+1 차단 시험 둘 다 필수. 유지 모드 경계 차단은 권장(필수로 확대하지 않음) | TC-R05 | L-1 차단만 있고 U+1 차단이 없으면 보완 필요 |
| T-5 | 모드 전환 시 기존 온도가 새 범위 밖일 때 동작을 요청/SRS가 정하지 않았으면 기대값을 만들지 말고 질문 | TC-R06 | 다른 모드 L-1에서 M으로 전환할 때 "자동으로 L"을 근거 없이 적으면 보완 필요 |
| T-7 | 한 모드의 경계 시험(L·U 적용, L-1·U+1 차단)은 한 TC에 모음 | TC-R02 | 같은 모드의 경계가 여러 TC에 흩어지면 보완 필요(표현 차이만으로 FAIL 아님) |
| T-8 | 차단 판정은 값이 그대로인지(패널·카드·내부값)만. 안내 문구·색상·비활성화는 요청에 없으면 기대결과 아님 | TC-R04·R06 | "U+1 시도 후 U 유지" = 충족, "경고 문구 표시"를 정답으로 단정 = 보완 필요 |
| C-3 | 적용 결과는 같은 조작 시점의 패널·카드·내부값 세 곳을 직접 기재. 내부값 누락은 오답 | TC-R04 | 패널·카드만 확인하면 보완 필요 |
| C-9 | 화면값과 내부값은 같은 대상 장비끼리 대조 | TC-R01·R04 | 대상 장비 화면과 다른 장비 내부값 비교는 보완 필요 |

요청이 시험 범위를 명시적으로 한정했다면 그 한정이 우선합니다. 이 규칙은 누락·추가를 판단하는 기준이며 제품 동작이나 실행 성공의 근거가 아닙니다. 과거 점수는 이 규칙으로 다시 매기지 않습니다.

## 판정 방법과 권한

- 항목별 `충족 / 보완 필요 / 해당 없음 / 근거 확인 필요`와 실제 TC 인용을 기록합니다.
- 코드 검사는 빈 문장·조건 연결·판정 시점 등의 구조적 오류만 검사합니다. 이 문서를 작성했다고 의미 평가가 자동화되는 것은 아닙니다.
- 상세도 검토는 요구사항 충실성, 실제 실행 성공, 사람의 공식 자산 승인과 별개입니다.
- [최초 대조 기록](TC_REFERENCE_REVIEW.md)은 Codex의 검토 결과이며 사람 검토 완료나 독립 LLM Judge 결과가 아닙니다.
