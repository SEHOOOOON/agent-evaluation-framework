에이전트 결과 검증

AI가 만든 QA 결과를 그대로 믿어도 될까요?
프로그램, AI, 사람이 나눠서 확인합니다.

프로젝트1은 변경 요청을 받으면 AI가 요구사항을 분석하고 테스트케이스(TC)를 만든 뒤 가상 제품에서 시험하고 보고하는 QA 자동화입니다. 프로젝트2는 그 결과를 채점해 믿을 만한지 확인하는 평가 도구입니다.

실무에서 테스트 결과를 볼 때 PASS·FAIL만 보지 않고 요구사항에 맞는 검사를 했는지와 근거가 충분한지도 함께 봤습니다. 이 관점을 프로젝트1에 적용해 결과를 단계별로 평가하고 문제가 나오면 프로젝트1을 고쳐 다시 실행했습니다.

찾은 문제

AI가 통과시킨 TC에서 누락 2가지

범위 끝 값 시험과, 시험 뒤 원래 상태로 되돌렸는지 확인이 빠져 있었습니다.

고친 뒤

다시 만든 TC 8번 모두 포함

규칙을 넣고 같은 요청으로 TC를 8번 다시 만들어 필수 시험이 다 있는지 확인했습니다.

평가 AI 점검

점수 15개 중 4개가 후했음

사람이 다시 판단해 찾았고 채점 기준을 고친 뒤 12개는 모두 같았습니다.

직접 만든 것 채점 기준 26개, 필수 시험 목록과 대조 프로그램, 평가 AI 채점기(OpenAI·Claude), 반복 실행·재채점 도구 · Python, Claude API, OpenAI API, Pytest

01 · 왜 필요한가

시험이 실패한 것과 에이전트가 실수한 것은 다릅니다.

FAIL 개수만 세면 틀린 결론을 내리기 쉽습니다. 같은 결과라도 원인에 따라 고칠 곳이 다릅니다.

제품이 요구사항과 다르게 동작

제품을 고쳐야 함

예: 잠금을 걸었는데 온도 버튼이 계속 눌림. 에이전트가 이 차이를 찾아 근거와 함께 보고했다면 할 일을 한 것입니다.

고칠 곳: 제품

필요한 검사를 빠뜨리고 통과

에이전트를 고쳐야 함

예: 냉방 최저 온도를 20°C로 바꾸는 요청인데, 20°C가 실제로 설정되는지는 시험하지 않음. 결과가 모두 PASS여도 문제입니다.

고칠 곳: 프로젝트1

평가자가 근거를 받지 못함

평가 도구를 고쳐야 함

예: 원래 상태로 되돌린 기록이 원본에는 있는데 평가 AI에게 넘긴 자료에서 빠져 낮은 점수가 나옴. 점수만 보면 정상인 시험을 고치게 됩니다.

고칠 곳: 프로젝트2

정보가 부족해 질문을 남기고 멈춘 경우는 실패가 아니라 정상 동작으로 평가합니다.

02 · 평가 방법

무엇을 기준으로, 어떻게 평가하나

프로젝트1은 일을 네 단계(Agent 1~4)로 나눠 처리하고 단계마다 결과물을 남깁니다. 결과물마다 확인할 질문을 정해 두고 채점합니다.

두 프로젝트가 맞물리는 순서 프로젝트1이 결과물을 만듦 → 프로젝트2가 채점 → 문제 발견 → 프로젝트1 수정 → 다시 실행해 확인

무엇을 기준으로 · 단계마다 꼭 지켜야 하는 것

  1. Agent 1 · AI

    요구사항 분석 결과

    • 정해지지 않은 값을 추측하지 않고 질문했나
  2. Agent 2 · AI

    테스트케이스(TC)

    • 꼭 필요한 시험이 다 있나
  3. Agent 3 · 프로그램 + AI 근거 검토

    실행·되돌리기 기록

    • TC에 적힌 값과 시점 그대로 시험했나
  4. Agent 4 · 프로그램

    결과 보고서

    • 실패·미실행·질문을 빠뜨리지 않았나

어떻게 · 누가 채점하나

프로그램계산으로 확인할 수 있는 것예: 꼭 있어야 하는 시험(필수 시험) 5개가 TC에 다 있는가, 보고서 개수가 실행 기록과 같은가
AI내용을 읽어야 판단할 수 있는 것예: 다른 사람이 이 절차를 그대로 따라 할 수 있는가. 0~5점과 이유를 남김
사람기준을 정하고 AI 점수를 다시 확인예: AI가 준 5점이 맞는가. 다르면 채점 기준을 고침

단계마다 이런 질문을 모아 기준 21개를 만들었고 기준마다 0~5점으로 채점합니다. 설계한 26개 중 나머지 5개는 아직 판정 전입니다. 기준별 점수 보기 →

교차 검수 평가 AI는 프로젝트1의 결과를 만든 AI(OpenAI)와 다른 회사 모델인 Claude를 씁니다. 같은 모델이 자기가 만든 결과를 채점하지 않게 하려는 것입니다.

03 · 사례 1

AI가 통과시킨 TC에서 빠진 경계값 시험을 찾았습니다.

"냉방은 20°C 아래로 내려가지 않게, 난방은 지금처럼 16°C까지" 요청을 프로젝트1로 실행했습니다. 프로젝트1의 검토 AI는 이 TC를 통과시켰고 이 도구의 평가 AI는 5점 만점을 줬습니다.

  1. AI 판단

    통과 · 5점

    프로젝트1의 검토 AI와
    이 도구의 평가 AI 모두 통과

  2. 사람이 다시 확인

    필수 시험 5개 중 3개

    범위 양 끝을 반쪽씩만 확인
    20°C 설정, 31°C 막힘이 없음

  3. 규칙 추가 후

    8번 모두 5개

무엇이 빠졌나: 범위의 양 끝

범위가 바뀌면 양쪽 끝에서 안쪽 값은 설정되는지와 바로 바깥 값은 막히는지를 둘 다 봐야 합니다. 처음 TC는 아래쪽은 막히는지만, 위쪽은 설정되는지만 봤습니다. 그래서 새로 바뀐 20°C가 실제로 설정되는지는 시험하지 않았습니다.

어떻게 고쳤나

  1. 왜 놓쳤는지 확인채점 기준이 "경계값을 확인했는가"처럼 막연해서 한쪽 끝만 본 TC도 만점이었습니다.
  2. 규칙으로 적기"범위 끝은 설정되는 값과 막히는 값을 각각 시험한다"처럼 구체적으로 적었습니다.
  3. 세 곳에 같은 규칙프로젝트1의 TC 작성 지침과 자동 검사, 이 도구의 필수 시험 대조에 넣었습니다.
  4. 다시 실행같은 요청으로 TC를 8번 다시 만들었고 8번 모두 필수 시험 5개가 다 있었습니다.

이 누락은 사람이 실행 결과를 검토하다 먼저 찾았고 그 뒤에 규칙과 필수 시험 목록을 만들었습니다. 이후 실행부터는 이 목록을 실행 전에 정해 두고 대조했습니다.

04 · 사례 2

지침만으로는 막지 못한 누락, 원인은 데이터 형식이었습니다.

온도 시험은 준비 단계에서 운전 모드를 냉방이나 난방으로 바꿉니다. 그런데 시험 뒤 확인에는 설정 온도만 있고, 모드를 되돌렸는지는 없었습니다. AI 채점, 프로그램 대조, 사람 확인에서 모두 같은 문제가 나왔습니다.

TC의 "시험 뒤 원래 상태 확인" 부분

같은 요청으로 TC를 다시 만들어 비교했습니다.

고치기 전 · 4번 모두 빠짐

바꾼 값 중 하나만 확인

  • 설정 온도가 시험 전 값으로 돌아옴✓ 있음
  • 운전 모드가 시험 전 값으로 돌아옴✗ 없음

채점: 되돌리기 확인 기준 3점

  • 설정 온도가 시험 전 값으로 돌아옴✓ 있음
  • 운전 모드가 시험 전 값으로 돌아옴✓ 있음

실제 실행에서도 시험 뒤 원래 상태로 돌아옴

바로 고치지 않고 같은 요청을 여러 번 실행했고 4번 모두 같은 누락이 나왔습니다. 지침 문장만 고쳐서는 해결되지 않았습니다. TC 데이터 형식에 준비 때 바꾼 값을 되돌렸는지 적을 칸이 없던 것이 원인이었습니다. 칸을 추가하고 비어 있으면 프로젝트1의 자동 검사에서 막도록 한 뒤 다시 만든 TC 3번 모두 모드 확인이 들어갔습니다. 개선 기록 →

05 · 평가 AI 검증

평가 AI의 점수도 사람이 다시 확인했습니다.

AI 채점 점수를 사람이 하나씩 다시 판단했습니다. 처음 15개 중 4개가 달랐고 4개 모두 AI가 너무 후하게 준 경우였습니다. 기준을 고친 뒤 새로 실행한 같은 대표 요청 4개의 TC 관련 기준 12개를 다시 비교했고 모두 같았습니다.

후했던 네 가지는 범위의 한쪽 끝만 시험한 TC, 조작과 확인을 한 줄에 섞어 쓴 절차, 고쳐 쓸 TC를 두고 새로 만든 경우, 시험하지 않은 부분에 준 점수였습니다. 유형마다 채점 기준을 고쳤습니다. 유형별 수정 내용 →

반대로 정상 시험을 깎은 적도 있습니다. 원래 상태로 되돌린 기록이 있었는데 3점이 나왔습니다. 원본을 보니 평가 AI에게 넘긴 자료에 그 기록이 빠져 있었고 자료 전달 방식을 고친 뒤 5점이 됐습니다.

평가 AI는 OpenAI와 Claude를 같은 자료로 비교한 뒤 Claude로 정했습니다. 비교 결과 →

06 · 결과와 한계

대표 요청 5개의 결과와 남은 한계

기능별로 하나씩 고른 요청 5개를 실제 AI로 실행하고 평가했습니다. 전원·풍량·모드 요청은 채점한 기준이 모두 5점이었습니다. 잠금 요청은 정해지지 않은 조건을 질문하고 멈춰 분석 기준 4개만 채점했고 모두 5점이었습니다. 온도 요청은 두 기준이 깎여 평균 4.86점이었고 그 감점이 사례 2로 이어졌습니다. 기준별 점수표 →

점수만으로 합격을 정하지 않습니다. 사람이 기준을 정한 범위 안에서, 어디를 먼저 확인할지 알려 주는 역할입니다.

확인한 범위

  • 대표 요청 5개의 실제 실행을 네 단계별로 평가
  • 평가에서 찾은 누락 두 가지를 프로젝트1에서 고치고 다시 실행
  • 채점 기준을 고친 뒤 새 실행 결과 12개를 사람 판단과 다시 비교해 모두 일치

아직 남은 것

  • 위 점수는 교차 검수용 Claude로 바꾸기 전에, 결과를 만든 것과 같은 OpenAI 모델이 채점한 결과
