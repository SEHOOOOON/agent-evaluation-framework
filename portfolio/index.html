에이전트 결과 검증

AI가 만든 QA 결과를 그대로 믿어도 될까요?
프로그램, AI, 사람이 나눠서 확인합니다.

실무에서 테스트 결과를 볼 때 PASS·FAIL만 보지 않고, 요구사항에 맞는 검사를 했는지와 근거가 충분한지도 함께 봤습니다. 이 관점을 프로젝트1에 적용해 결과를 단계별로 평가하고, 문제가 나오면 프로젝트1을 고쳐 다시 실행했습니다.

왜 필요한가평가 방법사례 1 · 빠진 경계값 시험사례 2 · 빠진 복원 확인평가 AI 검증평가 결과범위와 한계

01 · 왜 필요한가

시험이 실패한 것과, 에이전트가 실수한 것은 다릅니다.

FAIL 개수만 세면 틀린 결론을 내리기 쉽습니다. 같은 결과라도 원인에 따라 고칠 곳이 다릅니다.

제품이 요구사항과 다르게 동작

에이전트는 잘한 것

예: 잠금을 걸었는데 온도 버튼이 계속 눌림. 에이전트가 이 차이를 찾아 근거와 함께 보고했다면 할 일을 한 것입니다.

고칠 곳: 제품

필요한 검사를 빠뜨리고 통과

에이전트를 고쳐야 함

예: 냉방 최저 온도를 20°C로 바꾸는 요청인데, 20°C가 실제로 설정되는지는 시험하지 않음. 결과가 모두 PASS여도 문제입니다.

고칠 곳: 프로젝트1

평가자가 근거를 받지 못함

평가 도구를 고쳐야 함

예: 복원 기록이 원본에는 있는데 평가 자료에서 빠져 낮은 점수가 나옴. 점수만 보면 정상인 시험을 고치게 됩니다.

고칠 곳: 프로젝트2

정보가 부족해 질문을 남기고 멈춘 경우는 실패가 아니라 정상 동작으로 평가합니다.

02 · 평가 방법

무엇을 평가하고, 누가 채점하나

프로젝트1은 요청 하나를 처리하면서 네 가지 결과물을 남깁니다. 결과물마다 확인할 질문을 정해 두고 채점합니다.

평가하는 결과물

  1. Agent 1 · AI

    요구사항 분석 결과

    • 바뀌는 조건과 그대로 둘 조건을 구분했나
    • 정해지지 않은 값을 추측하지 않고 질문했나
  2. Agent 2 · AI

    테스트케이스(TC)

    • 기존 TC를 고쳐 쓸지 먼저 봤나
    • 꼭 필요한 시험이 다 있나
    • 시험 뒤 원래 상태로 되돌렸는지 확인하나
  3. Agent 3 · 프로그램 + AI 근거 검토

    실행·복원 기록

    • TC에 적힌 값과 시점 그대로 시험했나
    • 시험 전 상태로 돌아왔나
  4. Agent 4 · 프로그램

    결과 보고서

    • 실제로 본 결과대로 보고했나
    • 실패·미실행·질문을 빠뜨리지 않았나

누가 채점하나

프로그램계산으로 확인할 수 있는 것예: 필수 시험 5개가 TC에 다 있는가, 보고서 개수가 실행 기록과 같은가
AI내용을 읽어야 판단할 수 있는 것예: 다른 사람이 이 절차를 그대로 따라 할 수 있는가. 0~5점과 이유를 남김
사람기준을 정하고 AI 점수를 다시 확인예: AI가 준 5점이 맞는가. 다르면 채점 기준을 고침

기준 하나를 예로 들면

기준
시험 뒤 원래 상태로 돌아왔는지 확인하는가 (TC 평가)
5점
준비와 시험에서 바꾼 값마다 되돌렸는지 확인하는 단계가 있다.
3점 이하
바꾼 값 중 일부만 확인한다. 예: 설정 온도는 확인하지만, 준비 때 바꾼 운전 모드는 확인하지 않는다.
판단 보류
평가에 필요한 기록이 없으면 점수를 주지 않고 사람에게 넘긴다.

이런 기준 21개로 채점합니다(설계한 26개 중 5개는 아직 판정 전: 역할을 넘는 지시 1개, 단계 연결 4개). 지금 채점 AI는 프로젝트1의 생성 AI(OpenAI)와 다른 회사 모델(Claude)입니다. 06의 대표 요청 점수는 Claude로 바꾸기 전에 생성과 같은 OpenAI 모델로 채점한 결과입니다. 기준별 점수 보기 →

03 · 사례 1

AI가 통과시킨 TC에서 빠진 경계값 시험을 찾았습니다.

"냉방은 20°C 아래로 내려가지 않게, 난방은 지금처럼 16°C까지" 요청을 프로젝트1로 실행했습니다. 프로젝트1의 검토 AI는 이 TC를 통과시켰고, 이 도구의 채점 AI는 5점 만점을 줬습니다.

  1. AI 판단

    통과 · 5점

    프로젝트1의 검토 AI와
    이 도구의 채점 AI 모두 통과

  2. 사람이 다시 확인

    필수 시험 5개 중 3개

    범위 양 끝을 반쪽씩만 확인
    20°C 설정, 31°C 막힘이 없음

  3. 규칙 추가 후

    8번 모두 5개

    같은 요청으로 TC를 8번 다시 만들어
    8번 모두 5개가 다 있음

무엇이 빠졌나: 범위의 양 끝

범위가 바뀌면 양쪽 끝에서 안쪽 값은 설정되는지와 바로 바깥 값은 막히는지를 둘 다 봐야 합니다. 처음 TC는 아래쪽은 막히는지만, 위쪽은 설정되는지만 봤습니다. 그래서 새로 바뀐 20°C가 실제로 설정되는지는 시험하지 않았습니다.

어떻게 고쳤나

  1. 왜 놓쳤는지 확인채점 기준이 "경계값을 확인했는가"처럼 막연해서, 한쪽 끝만 본 TC도 만점이었습니다.
  2. 규칙으로 적기"범위 끝은 설정되는 값과 막히는 값을 각각 시험한다"처럼 구체적으로 적었습니다.
  3. 세 곳에 같은 규칙프로젝트1의 TC 작성 지침과 자동 검사, 이 도구의 필수 시험 대조에 넣었습니다.
  4. 다시 실행같은 요청으로 TC를 8번 다시 만들었고, 8번 모두 필수 시험 5개가 다 있었습니다.

이 누락은 사람이 실행 결과를 검토하다 먼저 찾았고, 그 뒤에 규칙과 필수 시험 목록을 만들었습니다. 이후 실행부터는 이 목록을 실행 전에 정해 두고 대조했습니다.

04 · 사례 2

지침만으로는 막지 못한 누락, 원인은 데이터 형식이었습니다.

온도 시험은 준비 단계에서 운전 모드를 냉방이나 난방으로 바꿉니다. 그런데 시험 뒤 확인에는 설정 온도만 있고, 모드를 되돌렸는지는 없었습니다. AI 채점, 프로그램 대조, 사람 확인에서 모두 같은 문제가 나왔습니다.

TC의 "시험 뒤 원래 상태 확인" 부분

같은 요청으로 TC를 다시 만들어 비교했습니다.

고치기 전 · 4번 모두 빠짐

바꾼 값 중 하나만 확인

  • 설정 온도가 시험 전 값으로 돌아옴✓ 있음
  • 운전 모드가 시험 전 값으로 돌아옴✗ 없음

채점: 복원 기준 3점

고친 뒤 · 3번 모두 포함

  • 설정 온도가 시험 전 값으로 돌아옴✓ 있음
  • 운전 모드가 시험 전 값으로 돌아옴✓ 있음

실제 실행에서도 시험 뒤 원래 상태로 돌아옴

  1. 반복되는지 확인바로 고치지 않고 같은 요청을 여러 번 실행했습니다. 4번 모두 같은 누락이 나왔습니다.
  2. 원인 찾기TC 데이터 형식에 "준비 때 바꾼 값"의 복원 확인을 적을 칸이 없었습니다.
  3. 원인 고치기칸을 추가하고, 비어 있으면 프로젝트1의 자동 검사에서 막도록 했습니다.
  4. 다시 실행TC를 3번 다시 만들어 모두 모드 확인이 들어갔고, 실제 실행에서도 원래 상태로 돌아왔습니다.

적을 칸이 없었기 때문에, 지침 문장만 고쳐서는 해결되지 않았습니다.

07 · 범위와 한계

AI 평가는 사람이 먼저 볼 곳을 찾는 도구입니다.

점수만으로 합격을 정하지 않습니다. 사람이 기준을 정한 범위 안에서, 어디를 먼저 확인할지 알려 주는 역할입니다.

확인한 범위

  • 대표 요청 5개의 실제 실행을 네 단계별로 평가
  • 전원·풍량·모드는 시험 설계를 각 3번 반복해 3번 모두 필수 조건 충족
  • 평가에서 찾은 누락 두 가지를 프로젝트1에서 고치고 다시 실행
  • 채점 기준을 고친 뒤 새 실행 결과 12개를 사람 판단과 다시 비교해 모두 일치

아직 남은 것

  • 필수 시험을 프로그램으로 대조하는 것은 온도 범위 요청뿐
  • 단계 사이 연결 기준 4개는 최종 판정 전, 역할을 넘는 지시(C02)는 그런 지시가 든 요청이 없어 시험 전
  • 사람이 다시 확인한 항목은 27개(처음 15개 + 기준 수정 후 12개)로 적고, 기준을 만든 본인 1명이 판단해 다른 사람과의 일치도는 확인 전
  • 여러 장비, 새 기능 추가 같은 실제 업무 범위는 아직 평가하지 않음
