개인 프로젝트

프로젝트1은 요구사항이 바뀔 때마다 반복하던 QA 업무(분석·TC 작성·시험·보고)를 AI 에이전트로 자동화했습니다. 프로젝트2는 그 결과가 정말 기준을 지켰는지 다시 검증하는 평가 도구입니다.
두 프로젝트에서 가장 어려웠던 것은, 사람이 경험으로 아는 QA 기준을 AI가 같은 뜻으로 따르게 만드는 일이었습니다.

P1
PERSONAL · PROJECT 01 / V2

QA 에이전트 워크플로

QA Agent Pipeline · 가상 중앙제어 시스템

실무에서 요구사항이 바뀔 때마다 기존 TC를 검토하고, 시험 후 결과와 근거를 정리하는 일을 반복했습니다. 반복 업무는 AI에 맡기고, 사람은 변경의 타당성과 결과 판단에 집중할 수 있는지 확인하고자 만들었습니다.

만든 것요구사항 분석 → TC 작성 → 자동 시험·복원 → 보고를 AI 에이전트 4개가 나눠 맡고, 단계마다 검사를 통과해야 다음으로 넘어갑니다. 공식 TC 등록은 사람이 결정합니다.
결과실제 AI로 변경 요청부터 보고까지 2건 완주했습니다. 온도 범위 변경 요청에서는 아직 바뀌지 않은 제품의 차이(기대 20°C → 실제 19°C)를 찾아 보고했습니다.
배운 점정해진 시험의 실행·보고는 맡길 수 있었지만, 새 요청의 TC 설계는 사람이 기준을 규칙으로 정리해 둔 경우에만 믿을 만했습니다.

P2
PERSONAL · PROJECT 02

에이전트 결과 검증

Agent Evaluation · 프로젝트1 평가와 개선 기록

P1을 실무에 활용하려면, 한 번의 성공보다 여러 요청에서 같은 기준을 지키는지 확인해야 한다고 생각했습니다. 제품의 문제를 찾아낸 경우와, 에이전트가 필요한 검사를 놓친 경우를 구분하기 위해 만든 평가 도구입니다.

만든 것분석·TC 설계·실행·보고를 26개 기준으로 평가합니다. 숫자로 확인할 수 있는 것은 프로그램이, 의미 판단은 AI가, 정답 기준은 사람이 정합니다.
결과AI 검토와 AI 채점이 모두 통과시킨 TC에서, 사람이 필수 시험 3개가 빠진 것을 찾았습니다. 이 기준을 규칙으로 옮겨 같은 누락을 자동으로 다시 잡아내게 했습니다.
배운 점AI의 평가도 검증 대상입니다. 높은 점수만으로는 품질을 판단할 수 없었고, 사람 기준과의 대조가 필요했습니다.
