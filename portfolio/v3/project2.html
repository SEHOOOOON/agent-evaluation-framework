Project 02 · Agent Evaluation

AI가 통과시킨 결과도
다시 검증합니다

프로젝트1을 실무에 쓰려면 한 번의 성공보다, 여러 요청에서 같은 기준을 지키는지가 중요하다고 봤습니다. 에이전트의 분석·설계·실행·보고를 역할별로 평가하고, 제품 문제·에이전트의 검사 누락·평가 AI의 오판을 구분합니다.

핵심 사례 보기 평가 근거
26개평가 기준역할별 20 · 공통 2 · 단계 연결 4
3 / 6AI가 통과시킨 TC의 필수 시험 충족 수사람 기준을 코드 대조로 옮긴 결과 · FAIL
4건평가 과정에서 찾아 고친 평가 도구·P1 문제입력 누락·로그 잘림·보고 부족 등
19 / 20한 실행에서 AI 채점이 준 5점 비율점수 변별력 부족 · 보완 과제
01 · WHY

PASS·FAIL만으로는 알 수 없는 것

실무에서도 테스트 결과뿐 아니라 "요구사항에 맞는 검사를 했는지", "실패 근거가 충분한지"를 함께 봤습니다.

구분 1

제품이 틀린 경우

예: 하한 16°C인데 15°C로 내려감. 이를 찾아낸 에이전트는 잘한 것이므로 감점하지 않습니다.

구분 2

에이전트가 검사를 빠뜨린 경우

예: 상한 바로 위 값의 차단 시험이 없음. 시험이 모두 통과해도 문제입니다.

구분 3

평가 AI가 잘못 판단한 경우

예: 복원 기록이 있는데 평가 입력에서 빠져 낮은 점수. 점수를 믿고 정상 시험을 고칠 뻔했습니다.

02 · METHOD

누가 무엇을 판단하는가

값·개수·연결처럼 계산할 수 있는 것은 프로그램이, 의미 판단은 AI가, 정답 기준은 사람이 정합니다.

1 · 수집

P1 실행 기록

요청·SRS·분석·TC·실행 로그·복원·보고를 해시와 함께 모읍니다.

2 · 프로그램

값과 연결 대조

집계 수, 기대값, 증거 연결을 계산으로 확인합니다. (4개 기준)

3 · AI

의미 검토

요청과 산출물의 의미를 근거 번호를 인용해 평가합니다. (12개 기준, 혼합 10개)

4 · 사람

정답과 대조

사람이 확정한 기준과 평가 결과를 비교해 오판과 누락을 찾습니다.

평가할 근거가 부족하면 점수를 주지 않고 판단 보류로 남깁니다. 실행되지 않은 단계는 PASS로 세지 않습니다.
03 · KEY CASE

AI 검토와 AI 채점이 모두 통과시킨 TC

2026-10-15 온도 범위 변경 요청(냉방 20~30°C, 난방 16~30°C 유지)의 실제 실행입니다. 자동 검토만 믿었다면 놓쳤을 누락을 사람이 찾았습니다.

자동 검토 통과

P1 AI 검토(CP2) PASS, P2 AI 채점 TC 설계 5점

사람 대조

냉방 31°C 차단 없음, 20°C 적용 기대결과 없음, 모드 전환 질문 없음

규칙으로 확정

"바뀐 경계는 적용·차단을 각각 시험" 같은 규칙을 값 없이 정리해 P1 지침과 P2 정답지에 같은 문장으로 반영

코드로 재현

규칙으로 필수 시험 목록을 만들고 실제 TC와 대조해 같은 누락을 숫자로 확인

실제 저장 TC를 규칙 기반 정답지(range-oracle)로 대조한 결과 · 2026-10-16 저장 자료 재검사 · 필수 3/6 → FAIL
필수 시험규칙실제 TC
냉방 20°C 적용 확인바뀐 하한 적용MISSING준비 단계에서만 설정, 기대결과 없음
냉방 30°C 적용 확인상한 적용MET
냉방 19°C 차단 확인하한 바로 아래 차단MET
냉방 31°C 차단 확인상한 바로 위 차단MISSING
난방 17°C → 16°C 적용요청에 적힌 시험MET
난방 17°C에서 냉방 전환 시 처리 질문범위 밖 값의 전환 동작이 미정이면 질문MISSING
의미 · AI 채점 5점은 "초안 기준으로 감점 사유를 찾지 못함"이지 "사람 기준으로도 맞음"이 아니었습니다. 그래서 의미 판단은 AI에 맡기되, 계산할 수 있는 필수 조건은 코드로 따로 확인하도록 바꿨습니다. 규칙 반영 후 AI가 실제로 누락을 막는지는 다음 실행에서 확인합니다.
04 · FINDINGS

평가하면서 찾아 고친 것

평가 도구 자체의 문제와 P1의 문제를 구분해 기록했습니다. 원래 점수와 실패 기록은 지우지 않고 보존합니다.

발견원인보완과 결과
복원한 시험이 낮은 점수평가 AI 오판복원 기록이 평가 입력에서 빠짐기록 전달 후 같은 사례 재평가: 복원 항목 3점 → 5점P1 성능 향상이 아닌 평가 입력 보완
실패 로그 근거 부족으로 판단 보류평가 도구큰 로그가 통째로 제외됨해시 확인 후 끝부분을 포함하도록 수정: 두 항목 보류 → 5점
보고서의 통과 항목이 "미확인"P1 보고 부족실패 TC 안의 개별 결과를 읽지 않음평가 AI가 지적(5점 → 4점) → P1 검토서가 항목별 관찰값을 표시하도록 수정
필수 시험 누락을 통과P1 + 평가 기준범위 변경의 필수 시험 기준이 없음사람 확정 규칙을 지침·정답지·코드 대조에 반영 (위 사례)
