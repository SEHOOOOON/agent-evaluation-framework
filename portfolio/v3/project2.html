에이전트가 검사를 제대로 했는지,
결과를 근거에 맞게 보고했는지

프로젝트1을 실무에 활용하려면 한 번의 성공보다, 여러 요청에서 같은 기준을 지키는지 확인해야 한다고 생각했습니다. 에이전트의 분석·설계·실행·보고를 평가하고, 보완할 부분을 찾기 위해 만들었습니다.

01 · Purpose & background

AI가 처리한 결과를, 무엇으로 판단할까요?

실무에서는 테스트의 PASS·FAIL뿐 아니라, 요구사항에 맞는 검사를 했는지와 실패 근거가 충분한지를 함께 확인했습니다. 반복 업무를 맡기려는 P1에도 같은 관점이 필요했습니다.

제품의 문제를 정확히 찾아낸 시험과, 필요한 검사를 빠뜨린 시험은 다릅니다. 최종 결과만 보는 대신 어느 단계에서 무엇을 지켰고 놓쳤는지 비교하면, 사람이 검토할 부분을 더 구체적으로 찾을 수 있다고 생각했습니다.

상황예시평가
제품이 틀림하한 16°C인데 15°C로 내려감찾아냄 = 잘함감점하지 않음
에이전트가 검사를 빠뜨림상한 바로 위 값의 차단 시험이 없음누락시험이 전부 통과해도 문제
정상적인 보류정해지지 않은 온도를 추측하지 않고 질문올바른 처리미실행이어도 감점하지 않음
평가 AI가 잘못 판단복원 기록이 평가 입력에서 빠져 낮은 점수평가 오류P1이 아니라 평가 도구를 고침
02 · Method

요청부터 보고까지, 역할별로 평가합니다

  1. P1 결과 수집요청과 요구사항 문서, 분석·TC·실행·복원·보고 기록을 원본 해시와 함께 모읍니다.
  2. 기준과 근거 대조프로그램은 값·개수·연결을 확인하고, AI는 요청과 산출물의 의미를 근거 번호를 인용해 검토합니다.프로그램 4 · AI 12 · 혼합 10
  3. 역할별 결과 비교점수와 판단 이유를 함께 보고 누락·오판과 보완할 부분을 구분합니다.
Agent 1
요구사항 분석

Agent 2
TC 설계

기존 TC로 충분한지 확인했는가? 조작·기대결과·복원 방법이 구체적인가?

Agent 3
자동화 실행

TC에 적힌 대상·값·시점을 검사했는가? 실제 관찰과 복원 기록을 남겼는가?

Agent 4
결과 보고

관찰한 결과에 맞게 보고했는가? 실패·미실행·확인할 질문을 빠뜨리지 않았는가?

04 · Hardest problem

평가하는 AI에게도 기준을 알려 줘야 했습니다

P1의 AI에게 QA 기준을 전달하기 어려웠던 문제는, 그 결과를 평가하는 AI에서도 똑같이 나타났습니다.

01
근거를 빠짐없이 보여 줘야 했다복원 기록이 있었는데 평가 입력에서 빠져 낮은 점수가 나왔습니다. 점수만 믿었다면 정상 시험부터 고쳤을 것입니다.
입력 누락
02
기준이 느슨하면 모두 5점이 됐다"경계값을 확인했는가" 수준의 기준에서는, 한쪽 경계만 있어도 통과했습니다. 한 실행에서 AI 채점 20개 중 19개가 5점이었습니다.
점수 쏠림
03
그래서 계산할 수 있는 기준은 코드로 옮겼다사람이 확정한 규칙으로 필수 시험 목록을 만들고, 실제 TC와 코드로 대조합니다. 의미 판단만 AI에 맡깁니다.
역할 분리
배운 점 · AI 평가도 평가 대상입니다. 평가 AI가 무엇을 보고 판단했는지(입력)와 무엇을 기준으로 판단했는지(정답 기준)를 사람이 정하지 않으면, 점수는 높게 나와도 누락을 놓칩니다.
05 · Key case

AI 검토와 AI 채점이 모두 통과시킨 TC

2026-10-15 온도 범위 변경 요청(냉방 20~30°C, 난방 16~30°C 유지)의 실제 실행입니다.

  1. 자동 검토 통과P1 근거 검토(CP2) PASS, P2 AI 채점 TC 설계 5점.
  2. 사람 대조냉방 31°C 차단 없음, 20°C 적용의 기대결과 없음, 모드 전환 질문 없음.
  3. 규칙으로 확정"바뀐 경계는 적용과 차단을 각각 시험" 같은 규칙을 값 없이 정리해, P1 지침과 P2 정답지에 같은 문장으로 넣었습니다.
  4. 코드로 재현요청에서 옮긴 범위 값에 규칙을 적용해 필수 시험 목록을 만들고, 실제 TC의 조작·확인 순서와 대조했습니다.

06 · Findings

평가하면서 찾아 고친 것

평가 도구의 문제와 P1의 문제를 나눠 기록했습니다. 원래 점수와 실패 기록은 지우지 않습니다.

평가 입력

누락된 복원 기록을 전달하고 재평가

전원 사례의 복원 기록을 평가기에 전달하자 복원 항목(A3-01)이 3점 → 5점. 같은 저장 사례의 재평가이며 P1 성능 향상이 아닙니다.

평가 입력

TC 설명 부족과 자료 누락을 구분

기존 TC에 확인 방법이 부족한 경우와, 확인 기록이 있는데 평가 입력에서 빠진 경우가 있었습니다. 고칠 대상이 달라 같은 결함으로 묶지 않았습니다.

평가 도구

큰 실패 로그가 통째로 빠짐

크기 한도를 넘는 로그가 근거에서 제외돼 판단 보류가 났습니다. 해시 확인 뒤 끝부분을 포함하게 해 두 항목 보류 → 5점.

P1 보고 부족

통과한 항목이 "미확인"으로 표시

평가 AI가 지적(5점 → 4점)한 내용을 확인해, P1 검토서가 항목별 관찰값을 표시하도록 고쳤습니다.

07 · Practical use

실무에 적용할 수 있을까?

점수보다, 어디를 보완할지 설명할 수 있어야 합니다. 사례를 비교하면서 제품 문제, 에이전트의 검사 누락, 평가 자료의 부족을 구분할 수 있었습니다.

방식판단근거와 조건
프로그램 대조 (집계·증거 연결·실제 검사 기록)적용 가능계산으로 확인하므로 반복해도 같은 결과. 로컬 75개 비교 모두 일치
규칙 기반 정답지 대조조건부요청 유형마다 사람이 규칙과 범위 값을 정리해야 함. 정리된 유형에서는 누락을 숫자로 잡음
AI 의미 채점보조 도구사람이 먼저 볼 곳을 찾는 데 유용. 점수 단독으로 합격 판단 불가(5점 쏠림)
사람 대조 없는 자동 평가아직 아님사람 판단과의 일치율, 같은 조건 반복 일관성 측정 전

실무에서는 결과를 일일이 다시 확인하는 대신 "어디부터 검토해야 하는지"를 찾는 도구로 쓰는 것이 현실적입니다. 수동 검토 시간이 얼마나 줄었는지는 아직 측정하지 않았습니다.
