Project 02 · Evidence

평가 근거와 확인 범위

프로젝트2 소개에 쓴 수치가 어디서 나왔는지, 어떤 방식으로 확인했는지 정리했습니다. 실제 AI 실행, 저장 자료 재검사, 로컬 시험은 서로 다른 근거이므로 섞어서 세지 않습니다.

자료 구분로컬 100회26개 기준개선 이력
01 · SOURCES

세 가지 근거를 구분합니다

같은 "통과"라도 무엇으로 확인했는지에 따라 의미가 다릅니다.

실제 AI 실행

새 요청을 AI가 처리

유료 API로 분석·설계·검토·채점을 새로 수행한 결과입니다. 호출 수와 사용량을 함께 기록합니다.

예: 2026-10-09 전원 요청, 2026-10-15 온도 범위 요청

저장 자료 재검사

저장된 산출물을 다시 대조

새 AI 호출 없이, 보관한 실행 기록의 원본 해시를 확인하고 새 검사 코드로 다시 읽은 결과입니다.

예: 10-15 TC의 범위 정답지 대조(필수 3/6)

로컬 시험

준비한 입력으로 처리 확인

사람이 준비한 TC와 저장 자료를 현재 실행기에 넣어, 정해진 상황을 예상대로 처리하는지 봅니다. AI가 새로 판단한 결과가 아닙니다.

예: 20종 상황 × 5회

02 · KEY CASE

핵심 사례의 근거

프로젝트2 소개의 "AI가 통과시킨 TC" 사례입니다.

단계내용근거 종류
실행전체 흐름 FLOW-20261015-110607-bb73a2 · P1 Run RUN-20261015-110609-8E2600 · Checkpoint 1~4 PASS, 재작성 0실제 AI
자동 판단P1 근거 검토(CP2) PASS · P2 AI 채점 TC 설계 5점실제 AI
사람 대조필수 시험 누락 3개 발견 (냉방 31°C 차단, 20°C 적용 기대결과, 전환 질문)사람 검토
코드 대조범위 정답지로 실제 TC 대조: 필수 6개 중 3개 충족, 누락 3개가 사람 발견과 일치 → FAIL저장 자료 재검사
남은 확인규칙을 반영한 P1이 실제 실행에서 누락을 막는지미검증

원본 실행 폴더는 용량 때문에 저장소 밖에 보관하고, 해시와 판정 과정은 개선 기록 IMP-009에 남겼습니다.

04 · CRITERIA

26개 평가 기준

역할별 기준 20개, 공통 기준 2개, 단계 연결 기준 4개입니다. 판단 주체는 프로그램 4개, AI 12개, 혼합 10개로 나눴습니다.

영역기준 수무엇을 보나
Agent 1 · 요구사항 분석4변경·유지 조건과 명시 값 보존 · 정보 부족·미기재·금지 구분 · 영향 범위와 부분 진행 · 근거 인용의 의미 일치
Agent 2 · TC 설계8기존 TC 재사용·중복 방지 · TC 대상·시작 상태 · 조작 순서 재현성 · 조작과 판정 시점 연결 · 관찰 위치·값의 구체성 · 요청 조건의 검증 범위 충족 · SRS 근거 · 독립 실행·복원
Agent 3 · 자동화 실행4TC에서 계획까지 의미 보존 · 화면 요소 선택과 지원 범위 · 계획과 실제 검사 기록 일치 · 실제 시험·복원·증거와 완료 주장
Agent 4 · 결과 보고4원본 실행 행과 집계 정확성 · 증거에 따른 원인 분류 · 보고 대상·상태·증거 추적 · 미확인 범위·후속 행동·승인 구분
공통2필요 입력·버전·출처 연결 · 역할·권한과 충돌 지시 방어
단계 연결4조건부터 실제 시험까지 완료 범위 · 정보 부족의 단계 간 보존 · 실패·질문의 다음 절차 전달 · 사람 승인 전후 공식 자산 보호 최종 평가 남음

05 · HISTORY

개선 이력

모든 개선은 날짜·수정 전·수정 후·확인 근거를 같은 양식으로 남깁니다. 확인하지 않은 것은 "미검증"으로 적습니다.
