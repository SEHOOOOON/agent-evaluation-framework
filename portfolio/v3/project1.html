01 · BACKGROUND

실무의 반복 업무에서 출발했습니다

중앙제어 시스템을 검증하며 요구사항이 바뀔 때마다 같은 일을 반복했습니다. 판단은 사람이 하되, 반복되는 조작과 기록은 맡길 수 있는지 확인하고 싶었습니다.

문제 1

담당자마다 시험 범위가 다름

같은 요구사항이라도 어떤 경계값·회귀 TC를 넣을지 사람마다 달랐습니다.

문제 2

AI는 근거 없는 기대값을 만듦

예: "자동 모드 18~30°C"를 AI가 16~30°C로 바꿔 쓰면, 이후 TC와 시험이 모두 틀린 기준으로 진행됩니다.

문제 3

모호한 TC가 끝까지 전파됨

설계 단계의 모호함이 자동화와 보고까지 이어지면, 실패 원인을 제품 탓으로 오해하게 됩니다.

실제 회사 자료 대신 직접 만든 가상 중앙제어 제품과 예시 요구사항을 사용했습니다. 기획·검증 기준·시나리오 설계를 맡고, AI 코딩 도구를 활용해 구현했습니다.

02 · FLOW

분석 → 설계 → 실행 → 보고 → 사람 판단

입력은 변경 요청, 기존 요구사항(SRS), 기존 TC입니다. 각 단계는 앞 단계가 정한 기준을 다시 쓰지 않고 그대로 전달받습니다.

AGENT 1 · AI

요구사항 분석

요청을 SRS와 대조해 바뀌는 조건·유지할 조건·정보 부족을 나눕니다.

CP1 · 원문 값과 분석 값 대조
AGENT 2 · AI

TC 설계

기존 TC로 충분한지 비교하고, 부족한 시험만 새 TC로 작성합니다.

CP2 · 근거·절차·기대결과 검토
AGENT 3 · AI + 프로그램

자동화 실행

TC를 화면 요소에 연결하고, 검증된 계획만 Playwright 코드로 변환해 시험 후 원래 상태로 복원합니다.

CP3 · TC와 실행 계획 일치
AGENT 4 · 규칙 기반

결과 보고

제품 불일치·자동화 문제·환경 문제·근거 부족·미실행으로 분류해 보고합니다.

CP4 · 집계·근거·보고값 일치
사람 판단 · 결과와 기존 TC를 비교해 SRS 개정, TC 추가·대체, 미등록, 보류를 선택합니다. 자동 검사 통과는 등록 승인이 아닙니다.
단계가 멈추는 경우
  • 핵심 정보가 없으면 추측하지 않고 질문을 남긴 채 다음 단계로 넘어가지 않습니다.
  • 고칠 수 있는 오류는 검사 결과를 AI에 보내 정해진 횟수 안에서 다시 쓰고, 재검사를 통과해야 진행합니다.
  • 자동화할 수 없는 TC는 비슷한 기능으로 대신하지 않고 제외 사유와 함께 보고합니다.
  • 실행하지 않은 항목은 PASS로 세지 않습니다.
03 · CASES

실행 사례

저장된 실행 기록입니다. "시험이 통과했다"보다 "어떤 결과를 어떻게 구분했는가"를 보여 주는 사례를 골랐습니다.

실제 AI 전체 실행 · 2026-10-15

온도 범위 변경: 냉방 하한 16°C → 20°C, 난방 16~30°C 유지

새로 만든 요청으로 분석부터 보고까지 실제 AI로 실행했습니다. Checkpoint 1~4를 재작성 없이 통과했고, 시험 대상 제품은 아직 요청대로 바뀌지 않은 상태였습니다.

시험관찰보고
냉방 20°C에서 내림19°C로 내려감 (기대 20°C 유지)제품 불일치 후보제품이 변경 전이므로 예상된 결과
냉방 30°C 적용30°C 확인 항목 3개(ER-004~006) 모두 일치통과
난방 17°C → 16°C16°C 적용통과
이 실행의 TC를 사람이 다시 확인해 필수 시험 3개가 빠진 것을 찾았습니다. 아래 "4. 사람이 찾은 한계"와 프로젝트2에서 이어집니다.
정상 · 재사용

04 · LIMITS FOUND

사람이 찾은 한계와 보완

자동 검토를 통과한 결과도 사람이 다시 보면 빠진 것이 있었습니다. 발견한 문제는 사례별 예외가 아니라 공통 규칙으로 고쳤습니다.

2026-10-15 발견

범위 변경 요청의 필수 시험 누락

위 온도 실행의 TC는 AI 검토(CP2)를 통과했지만 세 가지가 빠져 있었습니다.

  • 냉방 31°C 차단 시험 없음 (새 상한 바로 위)
  • 냉방 20°C 적용을 준비 단계에서만 하고 기대결과 없음
  • 난방 17°C에서 냉방으로 바꿀 때의 동작을 질문하지 않음
보완 · 사람이 확정한 범위 변경 규칙(적용·차단 경계, 전환 질문 등)을 TC 작성·검토 지침에 추가. 새 실행에만 적용하고 과거 기록은 그대로 둠. 실제 AI가 규칙을 지키는지는 아직 확인 전
2026-10-16 보완

실패한 TC 안의 통과 항목이 "미확인"으로 표시됨

냉방 TC 하나가 실패하면, 같은 TC 안에서 통과한 30°C 확인까지 사람 검토서에 "개별 판정 미확인"으로 남았습니다. 평가 AI가 이 보고 부족을 지적했습니다.

보완 · 실행 로그의 기대결과별 관찰 기록을 읽어 "통과(관찰값 30)" / "불일치(관찰값 19)"로 나눠 표시. 기록이 없는 항목만 미확인으로 둠. 로컬 시험 확인
05 · DEMO

60초로 보는 세 가지 결과

정상 시험과 등록, 제품 불일치 보고, 정보 부족 시 부분 진행을 각 20초씩 보여 줍니다.

  • 00:00 정상 시험 → 사람 승인 후 SRS 반영·공식 TC 등록
  • 00:20 잠금 시험 실패 → 제품 불일치 후보 보고
  • 00:40 색상 미정 → 확정 범위만 시험하고 사람 검토

2026년 8~9월 저장 실행을 10월 9일에 편집한 영상입니다. 최신 코드로 새로 촬영한 것은 아닙니다.

06 · SCOPE

확인한 것과 아직 확인하지 않은 것

반복 작업을 연결하는 것과, 새 요청을 믿고 맡길 수 있는 것은 다른 문제였습니다.

확인함
  • 가상 제품에서 조작·관찰값 기록·복원·보고를 한 흐름으로 수행
  • 실제 AI 전체 실행 2건 완주, 제품 불일치와 정보 부족을 구분해 보고
  • 준비한 20종 상황 × 5회에서 예상 처리 100% 일치 (AI 새 판단 아님)
아직 확인 전
  • 같은 요청을 여러 번 새로 실행했을 때 AI 판단이 일관되는지
  • 추가한 범위 변경 규칙이 실제 AI 실행에서 누락을 막는지
  • 실제 제품·장비 환경에서의 동작

다음 단계는 코드·기준·입력을 고정한 뒤 같은 조건으로 5회 실행해 일관성을 확인하는 것입니다. 평가 방법은 프로젝트2에 있습니다.
