Personal project 01 · QA Agent Pipeline

요구사항에서 승인까지,
같은 기준으로 판단하기

요구사항이 바뀔 때마다 반복하던 QA 업무(영향 분석·테스트케이스 작성·시험·보고)를 AI 에이전트로 자동화한 개인 프로젝트입니다. 자동화하면서도 AI가 요구사항과 검증 기준을 지키도록 단계별 검사와 사람의 최종 판단을 연결했습니다.

목적
반복 작업은 AI에 맡기고, 사람은 변경이 맞는지와 결과 판단에 집중
내 역할
기획, QA 기준과 시나리오 설계. 구현은 AI 코딩 도구 활용
결과
실제 AI로 요청부터 보고까지 2건 완주, 제품의 요구사항 불일치를 찾아 보고
가장 어려웠던 것
사람이 경험으로 아는 QA 기준을 AI가 같은 뜻으로 따르게 하는 일

01 · Why

변경 요청마다 같은 일을 반복했습니다

중앙제어 시스템을 검증하면서, 요구사항이 하나 바뀔 때마다 아래 일을 반복했습니다.

  1. 영향 분석예: "냉방 최저 온도를 20°C로" → 어떤 화면·모드·기존 테스트가 영향을 받는지 찾기
  2. 테스트케이스(TC) 검토·작성기존 TC로 충분한지 보고, 경계값 같은 필요한 시험을 추가
  3. 시험과 원상 복구장비 상태를 바꿔 시험하고, 다음 시험을 위해 원래 상태로 되돌리기
  4. 보고실패가 제품 문제인지 시험 준비 문제인지 나눠 근거와 함께 정리

판단하는 시간보다 조작하고 기록하는 시간이 더 길었습니다. 또 같은 요구사항이라도 담당자마다 넣는 시험이 달랐습니다. 기준이 문서가 아니라 사람의 경험에 있었기 때문입니다.

그래서 목표는 "AI가 TC를 많이 만드는 것"이 아니라, 요구사항부터 시험 결과까지 같은 기준을 지키고, 근거 없는 판단을 막는 흐름을 만드는 것이었습니다.
02 · Test target

시험 대상: 직접 만든 가상 중앙제어 시스템

회사 자료 대신, 실무와 비슷한 가상 제품을 만들어 시험했습니다. 장비 16대의 운전·모드·온도·풍량·잠금을 중앙에서 제어합니다.

03 · How it works

분석 → TC 작성 → 시험 → 보고 → 사람 판단

에이전트 4개가 일을 나눠 맡고, 각 단계의 결과는 자동 검사를 통과해야 다음 단계로 넘어갑니다.

입력변경 요청 + 기존 요구사항 문서(SRS) + 기존 TC
↓
무엇을 시험할지 정합니다AI
AGENT 1 · 요구사항 분석
바뀌는 것과 모르는 것 구분

요청을 기존 요구사항과 대조해 바뀌는 조건과 유지할 조건을 나눕니다. 정해지지 않은 값은 추측하지 않고 질문으로 남깁니다.

→
AGENT 2 · TC 작성
기존 TC를 고르고, 부족한 시험만 작성

기존 TC로 확인할 수 있는 것은 재사용하고, 부족한 부분만 새 TC로 만듭니다.

↓ 검사를 통과한 TC만 전달
시험하고 결과를 남깁니다AI + 프로그램
AGENT 3 · 자동 시험
TC대로 조작하고 원래대로 복구

TC를 화면 요소에 연결해 자동으로 시험하고, 끝나면 시험 전 상태로 되돌렸는지 확인합니다.

→
AGENT 4 · 결과 보고
결과와 이유를 분류해 보고

제품 문제인지, 시험 준비 문제인지, 실행하지 못했는지 나눠 Slack·Notion으로 보고합니다.

↓
마지막 결정은 사람이 · 요구사항 변경 승인, TC 공식 등록·대체·보류

모든 단계가 지키는 세 가지 원칙

추측 금지
근거 없는 기대값은 만들지 않음

모르는 값은 질문으로 남기고, 확인된 범위만 시험합니다.

정직한 집계
실행 안 한 시험은 통과가 아님

자동화할 수 없는 시험은 제외하고 그 이유를 보고합니다.

사람 승인
자동 통과 ≠ 공식 등록

통과한 TC도 사람이 기존 TC와 비교한 뒤 등록합니다.

04 · Walkthrough

요청 하나로 따라가 보기

실제로 실행한 변경 요청 · 2026-10-15

"냉방은 20°C 아래로 내려가지 않게 해 주세요.
난방은 기존 16°C 하한을 유지해 주세요."

기존 요구사항설정 온도 16~30°C모든 모드 공통
새 요청냉방 20~30°C · 난방 16~30°C냉방 하한만 변경
01분석바뀌는 것: 냉방 하한 20°C. 유지할 것: 난방 16°C 하한, 30°C 상한
02TC 작성냉방 20°C에서 내림 버튼을 눌러도 20°C가 유지되는지, 난방은 17→16°C가 되는지 시험
03자동 시험제품은 아직 요청대로 바뀌지 않은 상태. 냉방이 19°C로 내려감
04보고기대값을 제품에 맞춰 바꾸지 않고 "요구사항과 다른 동작"으로 보고. 난방 시험은 통과
시험 결과 · 모든 단계의 자동 검사를 재작성 없이 통과
시험기대실제보고
냉방 20°C에서 내림20°C 유지19°C불일치제품 변경 전이라 예상된 결과
냉방 30°C 적용30°C30°C통과
난방 17°C → 16°C16°C16°C통과
그런데 사람이 다시 보니 · 이 TC는 자동 검사를 모두 통과했지만, 꼭 있어야 할 시험 3개가 빠져 있었습니다. 냉방 31°C가 막히는지, 냉방 20°C가 정상 적용되는지, 난방 17°C에서 냉방으로 바꾸면 어떻게 되는지(요구사항에 없으니 질문해야 함)입니다. 이것이 다음 절의 문제로 이어집니다.
05 · Hardest part

가장 어려웠던 점: AI에게 기준을 알려 주는 일

사람 QA에게는 "바뀐 범위의 하한과 상한을 확인하세요"면 충분합니다. AI에게는 무엇을, 몇 개, 어느 시점에 확인하라는 뜻인지까지 적어 줘야 했습니다.

01
양식과 기준을 자세히 줬더니AI가 요구사항의 숫자를 바꿔 썼습니다(18~30°C → 16~30°C). → 원문 숫자는 프로그램이 직접 대조하도록 바꿨습니다.
숫자 왜곡
02
단계마다 기준을 반복해 줬더니같은 요구사항을 단계마다 다르게 해석했고, 기준을 잘게 쪼개자 정상적인 TC까지 막혔습니다. → 이미 정한 내용은 프로그램이 그대로 넘기고, AI는 새 판단만 맡게 했습니다.
해석 차이
03
그래도 사람만 아는 기준이 남았습니다위 온도 요청에서 시험 3개가 빠진 이유는, 지침에 "하한과 상한을 확인"이라고만 적혀 있었기 때문입니다.
암묵적 기준
이전 지침

"변경 후 하한과 상한을 확인한다"

사람에게는 충분하지만, AI는 한쪽 경계만 시험해도 지켰다고 판단했습니다.

바꾼 지침 (일부)
  • 새 하한과 새 상한이 각각 적용되는지 따로 확인
  • 하한 바로 아래, 상한 바로 위가 막히는지 둘 다 확인
  • 모드를 바꿀 때의 동작이 정해지지 않았으면 추측하지 말고 질문
  • 화면·카드·내부값을 같은 시점에 확인
배운 점 · QA 기준의 상당 부분은 경험으로 아는 암묵지였습니다. AI가 따르게 하려면 말 → 규칙 → 프로그램 대조로 점점 구체화해야 했고, 너무 느슨하면 시험이 빠지고 너무 세세하면 정상 결과까지 막혔습니다. 새로운 유형의 요청마다 사람이 먼저 기준을 정리해야 한다는 점이 이 방식의 가장 큰 비용입니다.
06 · Results

결과

2건실제 AI로 변경 요청부터 보고까지 완주전원 정지 · 온도 범위 변경
100 / 100미리 준비한 20가지 상황 × 5회, 예상대로 처리프로그램 반복 검사 · AI의 새 판단은 아님
65 / 65시험 뒤 시험 전 상태로 복구 확인위 100회 중 화면 시험
3개자동 검사를 통과한 TC에서 사람이 찾은 누락지침 보완 · 효과는 다음 실행에서 확인

대표 사례 세 가지

01
새 시험은 만들고, 기존 시험은 재사용풍량 '중풍' 표시 변경 · 새 TC 1개 + 기존 '강풍' TC 1개를 함께 시험 → 사람 승인 후 공식 등록
통과
02
요구사항과 다른 동작을 찾아 보고잠금 기능 · 잠금 상태인데 온도 버튼이 눌리는 상태. 내부 잠금값은 맞아서, 화면까지 확인하지 않았다면 놓쳤을 차이
불일치
03
정해지지 않은 조건은 추측하지 않음알림 색상이 정해지지 않은 요청 · 확정된 부분만 시험하고 색상은 사람에게 질문
사람 확인

60초 영상 · 위 세 사례를 20초씩 보여 줍니다(2026년 8~9월 실행을 편집).

07 · In practice

실무에 쓸 수 있을까?

반복 작업을 자동으로 연결하는 것과, 새로운 요청을 믿고 맡기는 것은 다른 문제였습니다.

업무판단이유
정해진 TC 실행과 원상 복구쓸 수 있음준비한 상황에서 100% 예상대로 처리, 복구도 확인
결과 분류와 보고서 작성쓸 수 있음제품 문제·시험 준비 문제·미실행을 규칙으로 구분. 결함 확정은 사람
새 요청의 TC 작성초안 수준기준을 규칙으로 정리해 둔 유형에서만. 그 전에는 필요한 시험이 빠짐
처음 보는 유형의 요청을 맡기기아직 어려움사람이 먼저 기준을 정리해야 하고, 반복 실행 시 일관성도 아직 측정 전

실제 도입에는 담당자의 기준을 규칙으로 정리하는 시간(가장 큰 비용), 제품마다 화면·내부값을 읽는 연결 작업, 사람의 검토 시간이 필요합니다. 실행 비용은 온도 요청 한 건 기준으로 AI 호출 16회, 사용량 기준 약 2달러로 추정했습니다(청구액 아님).
