01 · 평가 점수

대표 요청 5개의 평균 점수

기능별로 하나씩 고른 대표 요청을 실제 AI로 실행하고 26개 기준으로 평가했습니다. 대부분 5점이었고, 온도 요청에서 두 기준이 깎였습니다.

잠금5.0질문 후 멈춤 · 4개 기준
전원5.0완주·통과 · 20개 기준
풍량5.0완주·통과 · 20개 기준
모드5.0완주·통과 · 20개 기준
온도4.86복원 확인 3점 · 정답 시험 4점

5점이 많다고 잘했다고 단정하지 않으려고, TC 관련 기준 12개는 사람이 다시 확인했습니다(03 사람 대조).

02 · 반복 확인

같은 요청을 다시 넣어도 같은 설계가 나오는가

AI는 같은 입력에도 매번 다른 답을 낼 수 있습니다. 분석 결과는 그대로 두고, 결과가 가장 많이 달라지는 TC 설계 단계만 요청별로 3번씩 다시 실행해 비교했습니다.

요청설계 검사기존 TC 처리다시 쓴 횟수대조에서 나온 문제
전원3번 모두 통과3번 모두 새로 만들기정답0없음
풍량3번 모두 통과3번 모두 기존 TC 고쳐 쓰기정답0없음
모드3번 모두 통과3번 모두 기존 TC 고쳐 쓰기정답2없음
온도 · 고치기 전3번 모두 통과2번 고쳐 쓰기, 1번 새로 만들기2모드 복원 확인 3번 모두 누락
온도 · 고친 뒤3번 모두 통과3번 모두 기존 TC 고쳐 쓰기정답1모드 복원 확인 3번 모두 포함

무엇을 대조했나: 설계 검사 통과, TC 개수, 기존 TC 처리, 화면 패널·장비 카드·내부값 세 곳 확인, 절차에 확인 문장이 섞였는지, 바꾼 값마다 복원 확인, 한자·일본 문자가 섞였는지. 다른 언어가 섞인 경우는 한 번도 없었습니다. 온도 요청은 전체 실행 2번을 더해 8번 모두 정답 시험 5개가 있었습니다.

다시 쓴 횟수: 첫 TC가 자동 검사에 걸려 한 번 더 쓴 경우입니다. 모드·온도에서 6번 중 4번 있었고, 다시 쓴 TC는 모두 통과했습니다.

03 · 사람 대조

사람이 정한 정답과 AI의 판단을 비교했습니다.

온도 범위 요청의 정답 시험

요청: 냉방은 20°C 아래로 내려가지 않게, 난방은 지금처럼 16°C까지. 실행 전에 사람이 정한 정답 시험 5개로, AI가 처음 만든 TC와 규칙을 넣은 뒤의 TC를 비교했습니다.

정답 시험왜 필요한가처음 TC규칙 추가 후
냉방 19°C 막힘새 최저값 바로 아래가 막히는지있음있음
냉방 20°C 설정새 최저값이 실제로 설정되는지없음있음
냉방 30°C 설정최고값이 그대로 설정되는지있음있음
냉방 31°C 막힘최고값 바로 위가 막히는지없음있음
난방 16°C 설정냉방 변경이 난방에 영향을 주지 않았는지있음있음

처음 TC에는 프로젝트1의 검토 AI와 이 도구의 채점 AI가 모두 5점을 줬습니다. 지금은 이 기준을 프로그램이 정답표와 대조해 채점합니다. 개선 기록에는 "6개 중 3개"로 남아 있는데, 당시 정답표에 요청 범위 밖 항목 하나가 들어 있었기 때문입니다.

04 · 개선 기록

찾은 문제를 같은 순서로 기록하고 고쳤습니다.

  1. 발견 기록어느 실행에서, 누가(AI 채점·프로그램·사람) 찾았는지 남깁니다.
  2. 맞는 감점인지원본과 대조해 평가자가 잘못 판단한 것이면 평가 도구를 고칩니다.
  3. 재발 확인한 번 나온 문제는 반복 실행으로 "4번 중 4번"처럼 횟수를 확인합니다.
  4. 원인과 수정AI 판단, 작성 지침, 데이터 형식·검사 코드 중 어디가 원인인지 찾아 고칩니다.
  5. 다시 실행합격 기준을 먼저 적고 다시 실행해 확인합니다. 고치기 전 기록은 지우지 않습니다.
